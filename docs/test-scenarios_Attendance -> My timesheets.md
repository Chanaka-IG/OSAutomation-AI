## Feature Reference (verified live, 2026-06-15)

### Routes
| Route | Purpose |
|---|---|
| `/web/index.php/time/viewMyTimesheet` | **My Timesheet** view (heading "My Timesheet", `<h6>`). Self-scoped to the logged-in employee. Accepts `?startDate=YYYY-MM-DD`. |
| `/web/index.php/time/editTimesheet/{id}` | **Edit Timesheet** form for timesheet `{id}` (heading "Edit Timesheet"). |
| `/web/index.php/time/viewEmployeeTimesheet` | Supervisor/Admin **Employee Timesheets** (the approve/reject view — *out of scope here*, referenced for security boundaries). |

The session user (admin) is mapped to employee **Ruwan Kumara** (`empNumber=1`, `employeeId=0001`); My Timesheet always renders *that* employee's data.

### Layout
- **Period selector**: `Timesheet Period` label, a **prev** (`‹`) and **next** (`›`) chevron button, and a read-only range field showing `YYYY-MM-DD to YYYY-MM-DD` with a calendar-picker affordance. Week runs **Sun→Sat** in this instance (week-start is configurable; columns mirror the workweek).
- **Grid (view mode)**: columns `Project` · `Activity` · seven day columns (e.g. `7 Sun` … `13 Sat`) · `Total`; a trailing **Total** row sums each day + the grand total. Day cells render `HH:MM`. Empty grid → a single **"No Records Found"** row.
- **Status + actions**: `Status: <state>` paragraph with an **Edit** button always, plus a **Submit** button only while `Not Submitted`.
- **No-timesheet state**: when no timesheet exists for the period, an info alert **"No Timesheets Found"** and a **Create Timesheet** button render instead of the grid.
- **Action log**: heading **"Actions Performed on the Timesheet"** with a table (`Actions` · `Performed By` · `Date`); empty until an action (Submit/Approve/Reject) occurs.
- **Edit mode** (`/time/editTimesheet/{id}`): heading "Edit Timesheet" + period heading. Each row = **Project** autocomplete (`Type for hints…`, option label `Customer - Project`) · **Activity** OXD select (`-- Select --`, options scoped to the chosen project) · seven day inputs (free-text, `HH:MM` or decimal) · a **delete-row** trash button. An **Add Row** button adds a blank row. Footer: **Cancel** / **Reset** / **Save**.
- **Self-scoped**: there is **no employee selector** (unlike "Employee Timesheets"). No Approve/Reject affordance for the owner.

### Behaviour (verified)
- On open the **current week** loads via `GET …/timesheets/default?date=<today>`; `‹`/`›` step one week.
- **Create Timesheet** is **enabled** for the current and past periods but **disabled** for **future** periods.
- States: `NOT SUBMITTED → SUBMITTED → APPROVED | REJECTED`. `allowedActions` returned per state:
  `Not Submitted` → `SUBMIT, MODIFY, VIEW`; `Submitted` → `MODIFY, VIEW` (no SUBMIT).
- **Submit** is immediate — **no confirmation dialog**; the status flips to `Submitted`, the Submit button disappears, and a `Submitted` row is appended to the action log (performer + today's date).
- An **empty** timesheet (zero rows) **can be submitted** (observed: the seeded current-week timesheet was `Submitted` with no entries).
- **Save** persists rows and returns to the view (no toast observed); each saved day shows its `HH:MM` and totals recompute.
- **Hours validation** (per day cell): values `>= 24`, non-numeric, or malformed → inline error **"Should Be Less Than 24 and in HH:MM or Decimal Format"**. `HH:MM` *and* decimal (e.g. `8`, `8.5`) are both accepted.
- A row needs a **Project** (which supplies its **Activities**) and an **Activity**; the Activity select is empty until a project is chosen.
- **Data dependency**: the Project autocomplete is empty unless ≥1 active **Project** (which requires a **Customer**) with ≥1 **Activity** exists. A fresh instance has **zero** projects — tests must seed Customer→Project→Activity first.

### API contract (verified)
| Method | Endpoint | Body / Notes |
|---|---|---|
| GET | `/api/v2/time/timesheets/default?date=YYYY-MM-DD` | `{ data: { id, status:{id,name}, startDate, endDate } }` for the week containing `date`; `data` empty when none exists. |
| POST | `/api/v2/time/timesheets` | `{ date }` → creates the `NOT_SUBMITTED` week containing `date`. |
| GET | `/api/v2/time/timesheets/{id}/entries` | rows + `meta.{ timesheet, sum:{label}, columns:{date:{total:{label}}}, dates[], employee, allowedActions[] }`. |
| PUT | `/api/v2/time/timesheets/{id}/entries` | `{ entries:[{ projectId, activityId, dates:{ "YYYY-MM-DD":{ duration:"HH:mm" } } }], deletedEntries:[] }`. |
| PUT | `/api/v2/time/timesheets/{id}` | `{ action:"SUBMIT" \| "APPROVE" \| "REJECT", comment? }` (Submit needs no comment). |
| GET | `/api/v2/time/timesheets/{id}/action-logs?limit=&offset=` | `{ data:[…], meta:{ total } }` — the action-log rows. |
| GET | `/api/v2/time/projects?onlyAllowed=false&model=detailed&customerOrProjectName=<q>` | autocomplete source. |
| GET | `/api/v2/time/project/{id}/activities?limit=…` | activities for a project. |
| POST | `/api/v2/time/customers` · `/api/v2/time/projects` · `/api/v2/time/project/{id}/activities` | seeding (Customer → Project → Activity). |
| GET | `/api/v2/leave/workweek?model=indexed` · `/api/v2/leave/holidays?fromDate=&toDate=` | day-column structure + holiday markers. |

Entry response shape:
```jsonc
{ "data": [ { "project": {"id":10,"name":"…"}, "customer": {"id":5,"name":"…"},
             "activity": {"id":1,"name":"Development"},
             "total": {"label":"08:00"},
             "dates": { "2026-06-08": {"id":1,"date":"2026-06-08","comment":null,"duration":"08:00"} } } ],
  "meta": { "sum": {"label":"08:00"},
            "columns": { "2026-06-08": {"total":{"label":"08:00"}} },
            "allowedActions": [ {"action":"SUBMIT"}, {"action":"MODIFY"}, {"action":"VIEW"} ] } }
```
