# Test Scenarios — Attendance → Employee Timesheets

> Feature: **Time → Timesheets → Employee Timesheets** (`/time/viewEmployeeTimesheet`, OrangeHRM OS 5.8).
> The pipeline argument is *Attendance → Employee timesheets*; the screen lives under the **Time** module
> breadcrumb "Time / Timesheets". This is the **supervisor / admin** view used to look up a *subordinate's*
> timesheet and **Approve / Reject** it — the counterpart to the self-scoped *My Timesheet* view.
> Generated by `/create-scenarios`. Consumed by `/test-strategy`.

---

## Feature Reference (from domain skill + My-Timesheet sibling; UI selectors to be verified live in Step 4)

### Routes
| Route | Purpose |
|---|---|
| `/web/index.php/time/viewEmployeeTimesheet` | **Employee Timesheets** view. Has an **Employee Name** autocomplete + **View** button. After selecting an employee it renders *that* employee's timesheet grid for a week with period navigation. |
| `/web/index.php/time/viewMyTimesheet` | The self-scoped **My Timesheet** view (referenced for the security boundary; *out of scope here*). |

### Layout (Employee Timesheets)
- **Employee selector**: an **Employee Name** autocomplete (`Type for hints…`, options `First Last`) and a **View** button. Until an employee is chosen + View clicked, no timesheet grid is shown.
- **Period selector**: `Timesheet Period` label, **prev** (`‹`) / **next** (`›`) chevrons and a read-only `YYYY-MM-DD to YYYY-MM-DD` range field. Week runs **Sun→Sat** in this instance.
- **Grid**: columns `Project` · `Activity` · seven day columns · `Total`; trailing **Total** row; day cells render `HH:MM`. Empty grid → a single **"No Records Found"** row.
- **Status + actions**: a `Status: <state>` line. When the selected employee's timesheet is **Submitted**, **Approve** and **Reject** buttons render. **Reject** opens a modal/field requiring a **mandatory comment**. No Edit/Submit here (those belong to the owner on My Timesheet).
- **Action log**: heading **"Actions Performed on the Timesheet"** with `Actions` · `Performed By` · `Comment` · `Date`.
- **No-timesheet state**: when the employee has no timesheet for the period → **"No Timesheets Found"** info alert (no Create button — supervisors don't create on behalf in this view).

### Behaviour (from business rules; confirm live)
- A supervisor can view & action **only their subordinates**; an **Admin** can view **any** employee.
- States: `NOT SUBMITTED → SUBMITTED → APPROVED | REJECTED`. Approve/Reject are only valid against a **SUBMITTED** timesheet.
- **Approve** → `Status: Approved`; approved/submitted hours count toward project & attendance reports.
- **Reject** → requires a **mandatory comment**; moves the timesheet back to **NOT_SUBMITTED** so the employee can edit & resubmit; a `Rejected` row (with the comment) appends to the action log.
- A **non-supervisor ESS** user has no "Employee Timesheets" menu item and is denied the route.

### API contract (from `api-reference.md`; host = `env.baseURL`, prefix `/web/index.php/api/v2`)
| Method | Endpoint | Body / Notes |
|---|---|---|
| GET | `/time/employees/{empNumber}/timesheets?fromDate&toDate&limit&offset` | list an employee's timesheets in a range. |
| POST | `/time/employees/{empNumber}/timesheets` | `{ date }` → creates the week containing `date` (NOT_SUBMITTED). |
| GET | `/time/employees/{empNumber}/timesheets/{tsId}` | a single employee timesheet (meta incl. `allowedActions`). |
| PUT | `/time/employees/{empNumber}/timesheets/{tsId}/entries` | `{ entries:[{ projectId, activityId, dates:{ "YYYY-MM-DD":{ duration } } }], deletedEntries:[] }`. |
| PUT | `/time/employees/{empNumber}/timesheets/{tsId}` | `{ action:"SUBMIT" \| "APPROVE" \| "REJECT", comment? }` (Reject comment mandatory). |
| GET | `/time/employees/{empNumber}/timesheets/{tsId}/action-logs?limit&offset` | action-log rows. |
| GET / POST | `/time/customers` · `/time/projects` · `/time/project/{id}/activities` | seeding Customer → Project → Activity. |

> **Data strategy note (for downstream steps):** Approve/Reject need a *subordinate* with a **SUBMITTED** timesheet. Seeding plan: as Admin, locate/create a target employee, seed Customer→Project→Activity, create + populate + **submit** a timesheet for that employee via the `/time/employees/{empNumber}/…` API, then drive the supervisor view. Admin can view any employee, so the supervisor-subordinate relationship is only required for the *non-admin supervisor scoping* scenarios.

## TC-001–099 — Happy Path

### TC-001: Employee Timesheets opens with an employee selector
**Category**: Happy Path
**Preconditions**: Logged in as Admin/Supervisor.
**Steps**: Navigate to `/time/viewEmployeeTimesheet`.
**Expected Results**: Heading renders; an **Employee Name** autocomplete and **View** button are present; no timesheet grid until an employee is selected.
**Business Rule**: Employee Timesheets is a lookup-by-employee view.
**Suggested Layer**: E2E

### TC-002: Select an employee and view their timesheet
**Category**: Happy Path
**Preconditions**: A target employee with a timesheet for the current week.
**Steps**: Type the employee name → pick the option → click **View**.
**Expected Results**: The selected employee's timesheet grid loads for the current week; the period range and `Status:` line render for *that* employee.
**Business Rule**: Supervisor views a subordinate's timesheet.
**Suggested Layer**: E2E

### TC-003: Approve a submitted timesheet
**Category**: Happy Path
**Preconditions**: Target employee has a **SUBMITTED** timesheet for the viewed week.
**Steps**: View the employee's submitted timesheet → click **Approve**.
**Expected Results**: `PUT …/{empNumber}/timesheets/{id} {action:"APPROVE"}`; `Status: Approved`; Approve/Reject buttons disappear; an **"Approved"** row appends to the action log with the approver and today's date.
**Business Rule**: `SUBMITTED → APPROVED`.
**Suggested Layer**: E2E

### TC-004: Reject a submitted timesheet with a comment
**Category**: Happy Path
**Preconditions**: Target employee has a **SUBMITTED** timesheet.
**Steps**: View → click **Reject** → enter a comment → confirm.
**Expected Results**: `PUT …/{id} {action:"REJECT", comment}`; `Status: Rejected` (or back to *Not Submitted* per OS) and a **"Rejected"** action-log row with the comment.
**Business Rule**: `SUBMITTED → REJECTED`; reject comment mandatory.
**Suggested Layer**: E2E

### TC-005: Period navigation loads the employee's adjacent weeks
**Category**: Happy Path
**Preconditions**: An employee selected and viewed.
**Steps**: Click `‹` then `›`.
**Expected Results**: The period range steps back/forward exactly 7 days and the grid reloads for the same employee.
**Suggested Layer**: E2E

### TC-006: Action log shows the approval performer and date
**Category**: Happy Path
**Preconditions**: A timesheet just approved.
**Steps**: View the approved timesheet.
**Expected Results**: "Actions Performed on the Timesheet" lists `Approved` / `<approver name>` / `<today>`, matching `GET …/action-logs`.
**Suggested Layer**: E2E

### TC-007: A submitted timesheet's logged hours are visible to the supervisor
**Category**: Happy Path
**Preconditions**: Target employee submitted a timesheet with a known row (e.g. `08:00` Mon).
**Steps**: View it as the supervisor.
**Expected Results**: The grid shows the row's project/activity, the day value, and the row & grand totals matching what was seeded.
**Suggested Layer**: E2E

## TC-100–199 — Business Rules

### TC-104: Day columns mirror the configured week (Sun–Sat)

### TC-105: Per-day and grand totals equal the sum of the employee's entries

### TC-106: The viewed timesheet is the unique (employee, week) record

**Expected Results**: The same timesheet id loads; no duplicate.
**Suggested Layer**: API
