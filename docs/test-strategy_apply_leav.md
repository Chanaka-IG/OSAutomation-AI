# Test Strategy: Apply Leave (ESS)

> Input: `docs/test-scenarios.md` (29 scenarios). Generated by `/test-strategy`. Consumed by `/define-priority`.
> Goal: assign each scenario to the lowest adequate layer (pyramid, not ice-cream-cone).

## Layer Distribution
| Layer | Count | Focus | Approx. time |
|-------|-------|-------|--------------|
| Unit | 0 | No pure client-side logic exposed for this flow (day-count/balance live server-side) | — |
| API | 6 | Input-contract & balance/overlap rules validated directly against `/api/v2/leave/leave-requests` & `leave-balance` | fast |
| Component | 0 | No component-test harness in this repo; widget rendering folded into E2E | — |
| E2E | 23 | The ESS apply journey, status transitions, balance escrow, security, conditional UI | slow |

> Defense-in-depth: TC-102 (escrow), TC-103/104 (working-day count), TC-303/305 (balance), TC-304 (overlap) are validated at **both** API (assertion) and E2E (user action) layers.

## API Assignments

## Decision Rationale (contested)
- **TC-301/302 (required fields)** — input validation is an anti-pattern at E2E; primary layer is **API contract**. Kept OUT of the E2E priority list to avoid the ice-cream-cone (the generic "Required" behavior is already covered structurally by the Assign-Leave E2E suite). If desired, one representative required-field E2E can be added, but it is not release-gating here.
- **TC-403 (From>To)** — date-picker/range validation; primarily **API**; low E2E value (pickers usually prevent it). Deferred from E2E priority.
- **TC-102/103/104** — the *computation* is a backend rule → assert via **API balance delta** (deterministic), but the *user action* (apply via UI) is genuinely full-stack → keep an **E2E** that performs the apply and asserts the delta. Defense-in-depth.
- **TC-502/503 (widget/conditional UI)** — ideally component tests, but no component harness exists in this repo → fold into **E2E**.

## Anti-Patterns Checked (existing tests)
- The Assign-Leave E2E suite already asserts success via the **success toast** (not page heading) and verifies working-day counts via **API balance delta** — reuse those patterns here.
- Avoid testing pure required-field validation only at E2E for this feature; push the contract checks to API.
