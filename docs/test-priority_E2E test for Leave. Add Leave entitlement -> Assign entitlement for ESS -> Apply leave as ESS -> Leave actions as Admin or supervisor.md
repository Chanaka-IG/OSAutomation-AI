## Contested Calls

- **TC-004 → P0 (not P1)**: in production orgs the *supervisor* is the default approver; if supervisor approval breaks, the entire workflow stalls for every non-admin org. TC-005 (reject) stays P1 since reject volume is far lower and Admin can act as fallback.
- **TC-304 → P0 (not P1)**: overlap looks like "just validation", but a regression here creates **duplicate balance consumption** — data integrity, not UX.
- **TC-104 → P0 vs TC-400 → P2**: both are balance boundaries; TC-104 (exceed) corrupts data if it regresses, TC-400 (exact) merely exercises the happy boundary — failures there are visible and recoverable.
- **TC-008 → P1 (not P0)**: wide blast radius, but Individual mode (TC-001 seed path) is a full workaround, and it's a once-per-period admin task.
- **TC-302 → P1 vs TC-303 → P2**: both are Apply-form validation; date-order produces *plausible-looking wrong data* if missed, empty-required is self-evident and backend-guarded.
