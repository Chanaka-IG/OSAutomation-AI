# Test Scenarios: Dashboard (`/dashboard/index`)

> Feature: the post-login landing page — widget grid + quick launchers — for **Admin**,
> **ESS**, and **Supervisor** roles.
> Source: `orangehrm-opensource-domain` (SKILL.md Modules, ui-selectors.md Dashboard,
> api-reference.md Dashboard endpoints, user-flows.md Flow 1) **plus live-app ground truth
> captured via Playwright MCP on the kord instance (2026-06-06)**.
> Generated by `create-scenarios` skill.

## Context & Verified Ground Truth (live app, Admin role)

- Successful login redirects to `/web/index.php/dashboard/index`; topbar breadcrumb is an
  `<h6>` "Dashboard".
- **Admin sees 7 widgets** (`.orangehrm-dashboard-widget`): Time at Work, My Actions,
  Quick Launch, Buzz Latest Posts, Employees on Leave Today, Employee Distribution by
  Sub Unit, Employee Distribution by Location.
- **Quick Launch tiles (Admin)** (`.orangehrm-quick-launch-card`): Assign Leave,
  Leave List, Timesheets, Apply Leave, My Leave, My Timesheet. ESS users only get the
  self-service tiles (no Assign Leave / Leave List / Timesheets).
- Verified empty states: My Actions → "No Pending Actions to Perform";
  Employees on Leave Today → "No Employees are on Leave Today".
- Time at Work card (`.orangehrm-attendance-card`): punch status ("Not Punched In"),
  today total ("0h 0m Today"), week range ("Jun 01 - Jun 07") + weekly chart.
- 3 `<canvas>` charts render (Time-at-Work bar + two distribution pies).
- Widget data comes from `GET /api/v2/dashboard/employees/action-summary`, `…/leaves?date=`,
  `…/locations`, `…/subunit`, `…/time-at-work`, `…/shortcuts`, `GET /api/v2/buzz/feed`.
- **My Actions is the cross-module hook**: a Pending-Approval leave request for a
  subordinate/any employee surfaces "(N) Leave Requests to Approve" for the
  approver (Admin/Supervisor) — seedable via the leave self-apply API.
- Date caveat: "Employees on Leave Today" only lists leave on a *working* day — on
  weekends no leave can exist for "today" (work-week excludes it), so positive coverage
  of that widget must be state-agnostic or seeded on a working day.

## Happy Path (TC-001–099)

### TC-001: Admin lands on Dashboard after login with full widget grid

**Preconditions**: Valid Admin credentials.
**Steps**:

2. Observe redirect and the widget grid.

widgets render: Time at Work, My Actions, Quick Launch, Buzz Latest Posts, Employees on
Leave Today, Employee Distribution by Sub Unit, Employee Distribution by Location.

## Business Rules (TC-100–199)

### TC-100: Distribution charts are Admin-scope widgets
**Category**: Business Rule
**Preconditions**: Admin and ESS sessions.
**Steps**: Compare widget sets between Admin (TC-001) and ESS (TC-005).
**Expected Results**: "Employee Distribution by Sub Unit" / "by Location" render for
Admin; not for plain ESS (org-wide data is permission-gated).
**Business Rule**: Data-group permissions (§2).
**Suggested Layer**: E2E

### TC-101: My Actions empty state when nothing is pending
**Category**: Business Rule
**Preconditions**: Viewer has no pending approvals/self-reviews.
**Steps**: Open Dashboard as a fresh ESS user with no seeded actions.
**Expected Results**: My Actions shows "No Pending Actions to Perform".
**Business Rule**: Verified empty-state behavior.
**Suggested Layer**: E2E

### TC-102: Employees on Leave Today reflects approved leave for today only
**Category**: Business Rule
**Preconditions**: Working-day "today"; an employee with Scheduled leave covering today.
**Steps**: Open Dashboard as Admin.
**Expected Results**: The widget lists that employee; without such leave it shows
"No Employees are on Leave Today".
**Business Rule**: Widget reads `…/employees/leaves?date=<today>`.
**Suggested Layer**: API (UI variant is date-dependent — see Context caveat)

### TC-103: Quick Launch set follows role, not user
**Category**: Business Rule
**Preconditions**: Supervisor (ESS w/ subordinates).
**Steps**: Login as supervisor → Dashboard → read quick-launch tiles.
**Expected Results**: Self-service tiles present; admin-only tiles absent (supervisor
gains approval grids via menu, not extra admin launchers) — assert against the
`/dashboard/shortcuts` API for the session.
**Business Rule**: Shortcuts API drives tile visibility per role.
**Suggested Layer**: API

## Security (TC-200–299)

### TC-200: Unauthenticated dashboard access redirects to login
**Category**: Security
**Preconditions**: No session.
**Steps**: GET `/dashboard/index` directly.
**Expected Results**: Redirect to `/auth/login`.
**Business Rule**: §1 session enforcement; deep links bounce to login.
**Suggested Layer**: E2E

### TC-201: Dashboard APIs reject unauthenticated calls
**Category**: Security
**Preconditions**: No session cookie.
**Steps**: GET `/api/v2/dashboard/employees/action-summary` and `…/subunit` without auth.
**Expected Results**: 401/403 (or login redirect) — no data leak.
**Business Rule**: API session enforcement.
**Suggested Layer**: API

### TC-202: ESS session cannot read org-wide distribution APIs
**Category**: Security
**Preconditions**: ESS session cookie.
**Steps**: GET `/api/v2/dashboard/employees/subunit` and `…/locations` as ESS.
**Expected Results**: 403 (matches the missing widgets in TC-100); no org-wide counts
returned.
**Business Rule**: §2 data-group permissions at the API layer.
**Suggested Layer**: API

## Negative / Error (TC-300–399)

### TC-300: Session timeout on Dashboard returns to login with `next` param
**Category**: Negative

**Steps**: Clear cookies → navigate to `/dashboard/index`.
**Expected Results**: Redirect to `/auth/login` (deep-link redirect behavior per §1).
**Business Rule**: §1 — after logout/timeout any deep link forces login redirect.
**Suggested Layer**: E2E

### TC-301: Widget API failure does not blank the whole dashboard
**Category**: Negative
**Preconditions**: Admin session; one widget API mocked to 500.
**Steps**: Route-intercept `…/employees/subunit` → 500 → load Dashboard.
**Expected Results**: Other widgets still render; failed widget shows its empty/error
state; no full-page crash.
**Business Rule**: Widget isolation (§10 async loading).
**Suggested Layer**: E2E (route-mocked)
