# Test Scenarios — E2E Attendance: ESS submits a timesheet, Admin/Supervisor actions it

> Feature: the **cross-role timesheet lifecycle** (OrangeHRM OS 5.8, "Flow 5: Submit & Approve a Timesheet").
> An **ESS** user logs and **submits** their own weekly timesheet through `time/viewMyTimesheet`; then a
> different user (**Admin** or **Supervisor**) **Approves** or **Rejects** it through
> `time/viewEmployeeTimesheet`. The argument says "Attendance", but timesheets live under the **Time**
> module (breadcrumb "Time / Timesheets"); this is a *timesheet* flow, distinct from Attendance punch records.
> Generated by `/create-scenarios`. Consumed by `/test-strategy`.

---

## Feature Reference (verified live, 2026-06-15/16)

This flow spans **two screens already verified** in the sibling suites — see
`docs/test-scenarios_Attendance -> My timesheets.md` (ESS side) and
`docs/test-scenarios_Attendance -> Employee timesheets.md` (supervisor side). The *new* surface here is the
**hand-off between roles in a single end-to-end journey** and the state propagation across it.

### Roles & routes
| Actor | Route | Action |
|---|---|---|
| ESS (owner) | `/web/index.php/time/viewMyTimesheet` (+ `editTimesheet/{id}`) | Create / Edit / **Save** / **Submit** own timesheet. Self-scoped: no employee picker. |
| Admin / Supervisor | `/web/index.php/time/viewEmployeeTimesheet` → `viewTimesheet/employeeId/{empNumber}?startDate=` | Select the employee → **Approve** / **Reject** the *Submitted* timesheet (inline "Timesheet Action" card). |

### Lifecycle (verified)
- States: `NOT SUBMITTED → SUBMITTED → APPROVED | REJECTED`. Only `SUBMITTED`/`APPROVED` count toward Time reports.
- **ESS Submit** is immediate (no dialog): badge → `Submitted`, Submit button disappears, a `Submitted` row is appended to the action log (performer = ESS, today's date).
- **Supervisor Approve** → `Approved`; **Reject** → `Rejected`. Approve/Reject appear **only** for a `SUBMITTED` timesheet, and **never on the owner's own** My Timesheet view (you cannot action your own).
- **Reject comment is OPTIONAL** in OS 5.8 (UI and API accept an empty comment) — the domain skill's "mandatory comment" is Enterprise-only/stale. Reject sets state to **`REJECTED`** (not `NOT_SUBMITTED`).
- A non-supervisor ESS hitting `/time/viewEmployeeTimesheet` gets a **"Credential Required"** content panel.
- Data dependency: a row needs an active **Project** (with a **Customer**) + **Activity**; seed Customer→Project→Activity, and the ESS employee + login + a supervisor link to the approver.

### Cross-role API contract (host `env.baseURL`, prefix `/web/index.php/api/v2`)
| Method | Endpoint | Notes |
|---|---|---|
| POST | `/time/timesheets` `{date}` | ESS self-creates own week. |
| PUT | `/time/timesheets/{id}/entries` | ESS self-edits rows. |
| PUT | `/time/timesheets/{id}` `{action:"SUBMIT"}` | ESS self-submits. |
| POST | `/time/employees/{emp}/timesheets` `{date}` | Admin seeds on behalf (setup). |
| PUT | `/time/employees/{emp}/timesheets/{id}` `{action:"APPROVE"\|"REJECT", comment?}` | Supervisor/Admin action. |
| GET | `/time/employees/timesheets/{id}/entries` | Supervisor reads (meta.allowedActions). |

## TC-001–099 — Happy Path

### TC-001: ESS submits, Admin approves — full golden path
**Category**: Happy Path
**Preconditions**: ESS employee with a login, reporting to the approver; a Project/Activity seeded; a fresh week with no timesheet.
**Steps**: As ESS: open My Timesheet for the week → Create → Edit → pick Project/Activity, enter `08:00` → Save → Submit. Log out. As Admin: open Employee Timesheets → select the ESS employee → open the submitted week → Approve.
**Expected Results**: ESS badge `Submitted` after submit; Admin badge `Approved` after approve; API state `APPROVED`.
**Business Rule**: `NOT_SUBMITTED → SUBMITTED → APPROVED`.
**Suggested Layer**: E2E

### TC-002: ESS submits, Admin rejects with a comment
**Category**: Happy Path
**Preconditions**: As TC-001.
**Steps**: ESS submits a timesheet; Admin opens it and **Rejects** with a comment.
**Expected Results**: Badge `Rejected`; the comment + `Rejected` row appear in the action log; API state `REJECTED`.
**Business Rule**: `SUBMITTED → REJECTED`.
**Suggested Layer**: E2E

### TC-003: ESS adds a row, saves (toast), and submits
**Category**: Happy Path
**Preconditions**: ESS on a fresh week.
**Steps**: Create → Edit → Project/Activity + hours → Save → Submit.
**Expected Results**: `"Successfully Saved"` toast on Save; badge `Submitted`; the row + totals persist.
**Suggested Layer**: E2E

### TC-004: The action log captures both roles (submit + approve audit trail)
**Category**: Happy Path
**Preconditions**: A timesheet just submitted by ESS and approved by Admin.
**Steps**: View the approved timesheet's "Actions Performed on the Timesheet".
**Expected Results**: A `Submitted` row (ESS, date) **and** an `Approved` row (approver, date).
**Suggested Layer**: E2E

### TC-005: Rejected timesheet returns to the ESS, who edits and resubmits → Admin approves
**Category**: Happy Path
**Preconditions**: A timesheet ESS submitted and Admin rejected.
**Steps**: ESS reopens it (state `Rejected`), edits hours, resubmits; Admin approves.
**Expected Results**: ESS can modify after reject; resubmit → `Submitted`; Admin approve → `Approved`.
**Business Rule**: Reject returns the timesheet to the employee for correction.
**Suggested Layer**: E2E

## TC-100–199 — Business Rules

### TC-100: Supervisor sees Approve/Reject only for a SUBMITTED timesheet
**Category**: Business Rule
**Preconditions**: ESS has a `NOT_SUBMITTED` timesheet (created, not submitted).
**Steps**: Admin opens that employee/week.
**Expected Results**: No Approve/Reject (no "Timesheet Action" card); `allowedActions` excludes APPROVE/REJECT.
**Suggested Layer**: E2E

### TC-101: Approve/Reject transition the persisted state
**Category**: Business Rule
**Preconditions**: A submitted timesheet.
**Steps**: Approve one, reject another (fresh weeks); read state via API.
**Expected Results**: `APPROVED` / `REJECTED` respectively; re-action blocked.
**Suggested Layer**: API

### TC-102: One timesheet per employee per week across the lifecycle
**Category**: Business Rule
**Preconditions**: A week already submitted.
**Steps**: ESS re-opens the same week.
**Expected Results**: The same timesheet id; no duplicate created.
**Suggested Layer**: API

### TC-103: Only submitted/approved hours feed Time reports
**Category**: Business Rule
**Preconditions**: One approved and one not-submitted timesheet with hours.
**Steps**: Compare project/attendance report totals.
**Expected Results**: Only approved/submitted hours counted.
**Suggested Layer**: API

### TC-201: My Timesheet is self-scoped — ESS submits only their own

**Preconditions**: ESS logged in.
**Steps**: Inspect My Timesheet.
**Expected Results**: No employee selector; only the ESS's own timesheet is editable/submittable.
**Suggested Layer**: E2E

### TC-202: The owner cannot Approve/Reject their own timesheet
**Category**: Security
**Preconditions**: ESS viewing their own submitted timesheet (My Timesheet).
**Steps**: Inspect actions.
**Expected Results**: Only Edit (no Approve/Reject); approval lives in the supervisor view.
**Suggested Layer**: E2E

### TC-203: ESS cannot approve a timesheet via the supervisor API (privilege escalation)

**Steps**: `PUT /api/v2/time/employees/{emp}/timesheets/{id} {action:"APPROVE"}` as ESS.
**Expected Results**: `403`/forbidden; no state change.
**Suggested Layer**: API
