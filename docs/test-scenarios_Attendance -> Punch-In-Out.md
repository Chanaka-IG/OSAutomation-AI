## Feature Reference (verified live against the running instance, 2026-06-13)

### Pages / Routes
| Route | Purpose |
|---|---|
| `/attendance/punchIn` | Punch In form. **Auto-redirects to `/attendance/punchOut` when the user is already punched in.** |
| `/attendance/punchOut` | Punch Out form. Shows read-only *Punched in time* + *Punched In Note*, plus a new Date/Time/Note for the punch-out. |
| `/attendance/viewMyAttendanceRecord` | "My Attendance Records" list (self) — used to verify a saved record. |
| `/attendance/viewAttendanceRecord` | "Employee Attendance Records" (admin/supervisor) — list of employees + drill-in "View". |
| `/attendance/configure` | "Attendance Configuration" — 3 checkboxes controlling behaviour. |

### Punch In / Punch Out form fields
- **Date\*** — `input[placeholder="yyyy-mm-dd"]`. **Disabled** unless config `canUserChangeCurrentTime = true`.
- **Time\*** — `input[placeholder="hh:mm"]` (AM/PM format, e.g. `05:41 PM`). **Disabled** unless config `canUserChangeCurrentTime = true`.
- **Note** — `textarea.oxd-textarea` (placeholder "Type here"). **Optional** (no `*`).
- Action button: `In` on punchIn, `Out` on punchOut.
- Legend: `* Required` (only Date & Time are required).

### Configuration (`/attendance/configure`) — shared singleton, all OFF by default
1. *Employee can change current time when punching in/out* → `canUserChangeCurrentTime`
2. *Employee can edit/delete own attendance records* → `canUserModifyAttendance`
3. *Supervisor can add/edit/delete attendance records of subordinates* → `canSupervisorModifyAttendance`

### API contract (verified)
| Method | Endpoint | Body / Result |
|---|---|---|
| GET | `/api/v2/attendance/configs` | `{ canUserChangeCurrentTime, canUserModifyAttendance, canSupervisorModifyAttendance }` |
| GET | `/api/v2/attendance/current-datetime` | server current date/time (seeds disabled Date/Time fields) |
| GET | `/api/v2/attendance/records/latest` | `{ id, punchIn{...}, punchOut{...}, state{ id:"PUNCHED IN"|"PUNCHED OUT", name }, employee{...} }` |
| POST | `/api/v2/attendance/records` | Punch In — `{ date:"YYYY-MM-DD", time:"HH:mm", note?, timezoneOffset, timezoneName }` |
| PUT | `/api/v2/attendance/records` | Punch Out — same body shape; closes the latest open record (no id in URL) |

### Verified behaviour
- Punch In with default config uses **current server time** (fields disabled); on success the app **redirects to `/attendance/punchOut`** and shows the punched-in summary.
- Punch Out redirects back to **`/attendance/punchIn`** with a fresh empty form.
- A completed cycle appears in **My Attendance Records** with Punch In, Punch In Note, Punch Out, Punch Out Note, Duration (Hours), and a "(N) Record(s) Found" count + "Total Duration (Hours)".
- The admin account `admin` is mapped to employee **Ruwan Kumara** (empNumber 1).
- Attendance records are **independent of timesheets** (separate table — domain `business-rules.md` §6).

## TC-001–099 — Happy Path

### TC-001: Punch In at current time (default config)
**Category**: Happy Path
**Preconditions**: User logged in, mapped to an employee, currently **not** punched in; `canUserChangeCurrentTime = false`.
**Steps**:
1. Navigate to `/attendance/punchIn`.
2. Confirm Date & Time are pre-filled (disabled) with current server values.
3. Leave Note empty (or type a note), click **In**.
**Expected Results**: POST `/api/v2/attendance/records` returns 200; app redirects to `/attendance/punchOut`; the page shows *Punched in time* matching the submitted date/time and an **Out** button.
**Business Rule**: Punch In creates an open attendance record at the current time.
**Suggested Layer**: E2E

### TC-002: Punch In with a note, note persists on Punch Out screen
**Category**: Happy Path
**Preconditions**: Not punched in.
**Steps**:
1. Go to `/attendance/punchIn`, type a note (e.g. "Start of shift"), click **In**.
2. Observe the Punch Out screen.
**Expected Results**: Punch Out screen displays *Punched In Note* = "Start of shift" (read-only).
**Business Rule**: The punch-in note is stored and surfaced on the punch-out screen.
**Suggested Layer**: E2E

### TC-003: Punch Out closes the open record
**Category**: Happy Path
**Preconditions**: User is currently **punched in**.
**Steps**:
1. Navigate to `/attendance/punchIn` → auto-redirects to `/attendance/punchOut`.
2. Optionally add a punch-out note, click **Out**.
**Expected Results**: PUT `/api/v2/attendance/records` returns 200; app redirects back to `/attendance/punchIn` with the **In** button shown (state reset).
**Business Rule**: Punch Out closes the latest open record.
**Suggested Layer**: E2E

### TC-004: Full Punch-In → Punch-Out cycle produces one completed record
**Category**: Happy Path
**Preconditions**: Not punched in.
**Steps**:
1. Punch In with note "cycle-in".
2. Punch Out with note "cycle-out".
3. Open `/attendance/viewMyAttendanceRecord`.
**Expected Results**: A record row shows Punch In time, Punch In Note "cycle-in", Punch Out time, Punch Out Note "cycle-out", and a non-negative Duration (Hours); "(N) Record(s) Found" count increments by 1.
**Business Rule**: A completed cycle is one attendance record with a computed duration.
**Suggested Layer**: E2E

### TC-005: My Attendance Records shows total duration and record count
**Category**: Happy Path
**Preconditions**: At least one completed record exists for the day.
**Steps**: Open `/attendance/viewMyAttendanceRecord` for the relevant date.
**Expected Results**: "Total Duration (Hours)" equals the sum of row durations; "(N) Record(s) Found" matches the row count.
**Business Rule**: My Records aggregates daily attendance.
**Suggested Layer**: E2E

### TC-006: Punch In with an explicit past time (config ON)
**Category**: Happy Path
**Preconditions**: `canUserChangeCurrentTime = true`; not punched in.
**Steps**:
1. On `/attendance/punchIn`, Date & Time fields are **enabled**; set an earlier valid time today, click **In**.
**Expected Results**: Record saved with the chosen date/time; Punch Out screen reflects the chosen time.
**Business Rule**: When enabled, employees may set the punch time.
**Suggested Layer**: E2E

## TC-100–199 — Business Rules

### TC-100: Cannot Punch In twice — already-punched-in redirect

**Steps**: Navigate to `/attendance/punchIn`.
**Expected Results**: App redirects to `/attendance/punchOut` (heading "Punch Out", **Out** button). No second open record can be created.

**Business Rule**: Punch Out requires an open punch.

### TC-104: Note is optional on both Punch In and Punch Out

### TC-105: Punch record is independent of timesheets
