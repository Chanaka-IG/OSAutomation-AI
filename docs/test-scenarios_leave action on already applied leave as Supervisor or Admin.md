# Test Scenarios: Leave Action on Already-Applied Leave (Supervisor or Admin)

> Feature: Taking actions — **Approve / Reject / Cancel** (and **Comment**) — on leave
> requests that already exist in the system, performed from the **Leave List**
> (`/leave/viewLeaveList`) by an **Admin** (any employee) or a **Supervisor**
> (their subordinates only).
> Source: `orangehrm-opensource-domain` skill (business-rules.md §4 Leave Workflow,
> user-flows.md Flow 4), `ui-selectors.md` Leave List section.
> Generated by `create-scenarios` skill.

## Context & Key Domain Rules

- Leave status codes (DB int): `-1 Rejected, 0 Cancelled, 1 Pending Approval, 2 Scheduled, 3 Taken`.
- Workflow: **Pending Approval → Scheduled → Taken**, with **Rejected** and **Cancelled** as terminal off-ramps.
- Row **Action** options on the Leave List depend on current status:
  - *Pending Approval* → **Approve**, **Reject**, **Cancel** (and **Comment**).
  - *Scheduled* (already approved) → **Cancel** (and **Comment**).
  - *Rejected / Cancelled / Taken* → terminal; no Approve/Reject.
- Balance escrow: the "Pending Approval" portion is subtracted from balance **immediately on apply**.
  - **Approve** keeps it consumed (escrow → scheduled): balance unchanged.
  - **Reject / Cancel** returns the days to the employee's balance.
- **Self-approval is blocked** — a Supervisor cannot approve their own leave request.
- Only **Admin** and **Supervisors** reach the Leave List approval grid; **ESS** cannot.
  - Admin can action **any** employee. Supervisor can action **only direct/indirect subordinates**.
- API equivalent: `PUT /leave/leave-requests/{id}` `{ action: "APPROVE" | "REJECT" | "CANCEL" }`.

## Happy Path (TC-001–099)

### TC-001: Admin approves a Pending Approval leave request
**Category**: Happy Path
**Preconditions**: An employee has a Pending Approval leave request; logged in as Admin.
**Steps**:
1. Go to `/leave/viewLeaveList`.
2. Filter by employee + status "Pending Approval"; Search.
3. Open the row Action dropdown → select **Approve**.
**Expected Results**: Success toast; the request status changes to **Scheduled** (status 2).
**Business Rule**: Approve transitions Pending Approval (1) → Scheduled (2).
**Suggested Layer**: E2E

### TC-002: Admin rejects a Pending Approval leave request
**Category**: Happy Path
**Preconditions**: A Pending Approval request exists; logged in as Admin.
**Steps**: Search the request → Action dropdown → **Reject**.
**Expected Results**: Success toast; status changes to **Rejected** (status -1).
**Business Rule**: Reject transitions Pending Approval (1) → Rejected (-1), a terminal state.
**Suggested Layer**: E2E

### TC-003: Admin cancels a Pending Approval leave request

**Expected Results**: Success toast; status changes to **Cancelled** (status 0).

**Suggested Layer**: E2E

## Business Rules (TC-100–199)

### TC-100: Approving a pending request leaves the balance consumed (escrow → scheduled)
**Category**: Business Rule
**Preconditions**: Pending request exists (balance already escrowed); Admin.
**Steps**: Record balance → Approve → record balance.
**Expected Results**: Balance is **unchanged** by the approval (it was already escrowed at apply time).
**Business Rule**: Pending days are escrowed on apply; approval does not re-deduct.
**Suggested Layer**: E2E (balance read via API)

### TC-101: Rejecting a pending request returns the escrowed balance
**Category**: Business Rule
**Preconditions**: Pending request exists; Admin.
**Steps**: Record balance → Reject → record balance.
**Expected Results**: Balance **increases** by the request's day count (escrow released).
**Business Rule**: Reject releases the escrowed pending days.
**Suggested Layer**: E2E (balance read via API)

### TC-102: Cancelling a pending request returns the escrowed balance
**Category**: Business Rule
**Preconditions**: Pending request exists; Admin.
**Steps**: Record balance → Cancel → record balance.
**Expected Results**: Balance **increases** by the request's day count.
**Business Rule**: Cancel releases escrowed days.
**Suggested Layer**: E2E (balance read via API)

### TC-103: Cancelling a Scheduled (approved) leave returns the balance
**Category**: Business Rule
**Preconditions**: Scheduled request exists; Admin.
**Steps**: Record balance → Cancel the Scheduled request → record balance.
**Expected Results**: Balance increases by the day count.

**Suggested Layer**: E2E (balance read via API)

### TC-104: A Rejected request is terminal — Approve/Reject no longer offered

### TC-106: Supervisor cannot approve their own leave request (self-approval blocked)
