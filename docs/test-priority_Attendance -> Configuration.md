# Test Priority — Attendance → Configuration

> Input: `docs/test-strategy_Attendance -> Configuration.md`.
> Scope: **E2E scenarios only** (API-primary TC-006/102/103/201/203/300/301 are owned by the API layer).
> Generated by `/define-priority`. Consumed by `/generate-tests`.

Priority key: **P0** release-blocking · **P1** high impact · **P2** moderate · **P3** low/cosmetic.

---

## P0 — Release-blocking (core flow, security, data integrity, no workaround)

| ID | Scenario | Rationale |
|---|---|---|
| TC-002 | Enable a toggle + Save persists it | The core action of the screen; if Save doesn't persist, the feature is non-functional. |
| TC-004 | Saved config persists across reload | Data integrity — a config that silently reverts misconfigures the whole module. |
| TC-100 | `canUserChangeCurrentTime` ON makes Punch In Date/Time editable | The reason the config exists — proves the flag actually gates behaviour. No workaround. |
| TC-200 | ESS user cannot access Configuration | Security/compliance — an employee must not change instance-wide attendance policy. |
| TC-202 | Unauthenticated access redirects to login | Security baseline for the route. |

## P1 — High impact (primary path, high reach)

| ID | Scenario | Rationale |
|---|---|---|
| TC-001 | Page loads toggles in their saved state | Primary read path; admins must see the true current policy. |
| TC-003 | Disable a toggle + Save persists it | The inverse of the core save; equally important for turning policy off. |
| TC-005 | Enable all three toggles + Save | Full-config persistence in one save. |
| TC-402 | Disabling a flag reverts the downstream behaviour | Reversibility — turning policy off must actually restore the stricter default. |
| TC-503 | Success toast on save | The admin's only confirmation the save took. |
| TC-105 | Saving with no changes preserves state (idempotent) | Common admin action; must not corrupt state. |
| TC-500 | Three labelled toggles render with correct labels | Primary surface; mislabeling = wrong policy set by mistake. |
| TC-505 | Toggles load matching the saved config | No phantom unsaved diff; load fidelity. |

## P2 — Moderate (secondary flows, needs extra role/data, overlaps a P0/P1)

| ID | Scenario | Rationale |
|---|---|---|
| TC-101 | `canUserModifyAttendance` → self edit/delete affordance | Downstream effect; needs ESS + a seeded record. |
| TC-104 | PUT body matches the UI toggle state | Serialisation detail; backstopped by API. |
| TC-400 | On→off before save → final state saved | UI-state edge on the common path. |
| TC-403 | Change visible on next load | Overlaps TC-004; moderate. |

## P3 — Low / cosmetic

| ID | Scenario | Rationale |
|---|---|---|
| TC-501 | Toggle visually reflects on/off | Switch feedback; cosmetic. |
| TC-502 | Save button present | Static affordance. |
| TC-504 | Heading "Attendance Configuration" | Page-identity cosmetic. |
