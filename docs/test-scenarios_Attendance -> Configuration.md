## Feature Reference (verified live, 2026-06-14)

### Route
`/web/index.php/attendance/configure` — heading **"Attendance Configuration"** (`<h6>`). **Admin-only**,
single screen. A global **singleton** config for the whole instance.

### Controls — three OXD **switch** toggles + Save
| # | Label | Config key |
|---|---|---|
| 1 | Employee can change current time when punching in/out | `canUserChangeCurrentTime` |
| 2 | Employee can edit/delete own attendance records | `canUserModifyAttendance` |
| 3 | Supervisor can add/edit/delete attendance records of subordinates | `canSupervisorModifyAttendance` |

- Each toggle is an OXD switch: `.oxd-switch-wrapper` → clickable `.oxd-switch-input` span (the underlying
  `input[type="checkbox"]` is intercepted — click the span, per `[[pim-optional-fields]]`).
- **Save** button persists all three booleans. **Default on this instance: all OFF.**

### Behaviour (verified)
- Toggling a switch + **Save** → success toast **"Successfully Saved"** (`BasePage.verifySuccessToastForSave`)
  and the value persists (reflected by `GET …/configs` and on reload).
- The PUT body always carries **all three** booleans (current UI state), not just the changed one.
- Switches are independent; restoring requires writing the prior values back (singleton — tests MUST restore).

### Downstream effects (each toggle gates behaviour proven in the sibling pipelines)
- `canUserChangeCurrentTime` → Punch In/Out **Date/Time fields become editable** (else disabled → current time).
- `canUserModifyAttendance` → employees may **edit/delete their own** attendance records (My Records affordance).
- `canSupervisorModifyAttendance` → supervisors may **add/edit/delete subordinates'** records (Employee Records).

### API contract (verified)
| Method | Endpoint | Body / Result |
|---|---|---|
| GET | `/api/v2/attendance/configs` | `{ canUserChangeCurrentTime, canUserModifyAttendance, canSupervisorModifyAttendance }` |
| PUT | `/api/v2/attendance/configs` | `{ canUserChangeCurrentTime, canUserModifyAttendance, canSupervisorModifyAttendance }` → 200 |

- ESS users are denied the screen (**"Credential Required"**, verified in the Punch-In/Out pipeline).
