## P0 — Release-Blocking (core flow, data integrity, security, no workaround)

| ID     | Title | Rationale |
|--------|-------|-----------|
| TC-001 | Admin approves a Pending request → Scheduled | The single most important path of the feature; if approval fails the entire leave workflow is broken. No workaround. |
| TC-002 | Admin rejects a Pending request → Rejected | Core terminal action; reject must work to keep the queue manageable and balances correct. |
| TC-101 | Reject returns the escrowed balance | Data integrity — a reject that does not release escrowed days silently corrupts every future balance. No workaround. |
| TC-106 | Supervisor cannot self-approve their own leave | Security/compliance control; a broken self-approval gate is a release blocker. |
| TC-200 | ESS user cannot access the Leave List | Security — an ESS user reaching the approval grid can approve/reject arbitrary leave. |
| TC-201 | Unauthenticated access → login redirect | Security — unauthenticated reach to any leave action is release-blocking. |
