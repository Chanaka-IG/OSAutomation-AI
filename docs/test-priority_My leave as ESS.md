## Decision Rationale (contested)
- **TC-101 P1 vs P0** — the mandatory-status guard is critical, but searching itself (TC-001) is the release-gating core path; the guard is a high-impact rule, not the core journey → **P1**. Its negative twin TC-301 is **P2** to avoid double-gating the same behavior.
- **TC-006 (cancel) P0** — promoted above a generic "action" because it is the *only* mutating capability an ESS has on this page and it touches balance integrity; a broken cancel strands the employee with no workaround.
- **TC-104 (escrow) P1 not P0** — the balance math is also asserted deterministically at the **API** layer (strategy doc), so the E2E carries high but not sole responsibility.
- **TC-401 (no entitlement empty list) P2** — it is the guaranteed live state for a fresh ESS user (and a reliable pass), but business impact of an empty-state is moderate, so priority reflects impact, not convenience.
- **TC-202 vs TC-102** — both cover isolation; TC-102 (no selector at all) is the stronger structural guarantee → **P0**, while TC-202 (cannot query others) is the corroborating check → **P1**.
