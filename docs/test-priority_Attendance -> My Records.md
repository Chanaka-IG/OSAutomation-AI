## P0 — Release-blocking (core flow, security, data integrity, no workaround)

| ID | Scenario | Rationale |
|---|---|---|
| TC-001 | Opens defaulted to today and auto-loads today's records | The page's primary entry behaviour; if it doesn't load the current day, the feature is broken on arrival. |
| TC-002 | Filter by a date with records shows those records | The core purpose of My Records — query a date, see your punches. No workaround. |
| TC-005 | "(N) Records Found" equals the record count | Data integrity: a miscount misrepresents the employee's attendance. High reach. |
| TC-201 | Self-scope — no cross-employee data or selector | Privacy/compliance: an employee must never see another's attendance. |
| TC-203 | Unauthenticated access redirects to login | Security baseline for the route. |

## P1 — High impact (primary path, high reach)

| ID | Scenario | Rationale |
|---|---|---|

| TC-004 | Total Duration equals the API sum | High-trust number (payroll-adjacent); wrong totals erode confidence. |
| TC-006 | Changing the filter date updates the results | The filter is the page's main control; must re-query correctly. |
| TC-200 | ESS user can view their own records | High reach — every employee uses this self-service view. |

| TC-500 | Empty state → "No Records Found" + 0.00 + info toast | Every new user / empty day hits this; must render cleanly. |

### Notes for generation
- Reuse `MyAttendanceRecordsPage`, `AttendanceApi`, `test-data/time/frontend/attendance.ts` from the prior
  pipeline; extend the page object with date-filter methods and the API with `getRecordsByDate(date)`.
- Records can only be seeded at **current** server time (past/future punch rejected with config OFF), so
  data-bearing tests seed **today** via API and assert on **unique notes** / **relative counts**; the
  empty-state test uses a **far-past date** (e.g. 2015-06-14) that is always empty.
- ESS tests use `auth.essTestUser` (`marcus.chen`). My Records is self-service, so ESS access is *expected to
  succeed* (positive), unlike the admin Config/Employee-Records screens.
