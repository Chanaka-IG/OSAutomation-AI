## Decision Rationale (contested assignments)

- **TC-004/005/006 → P0.** Together they are the feature's reason to exist (create → log → submit). A
  failure in any one leaves the user unable to record or hand off time, with no workaround.
- **TC-009 → P1 over TC-102 (P2).** Both touch totals; TC-009 exercises the *user* journey (enter several
  days, see the row/grand totals) and is the higher-value, higher-reach assertion. TC-102 is the narrower
  correctness restatement and is also covered at API, so it drops to P2.
- **TC-103 → P1.** Decimal vs `HH:MM` is not cosmetic — users routinely type `8` or `8.5`; silently
  rejecting them would block the primary input path, so it ranks with the core entry flow.
- **TC-105 → P1, TC-505 → P2.** The *rule* (no future timesheets) is high-impact and ranks P1; the
  button-disabled *rendering* of that same rule is the lower-value UI restatement (P2).
- **TC-300 → P1, TC-301/302/304 → P2.** The ≥24 ceiling is the headline, highest-frequency validation and
  earns P1; the non-numeric / minutes>59 / negative variants are lower-frequency restatements of the same
  guard and sit at P2.
- **TC-202 → P0, TC-205 → P2.** Cross-employee edit access (IDOR) is a hard security boundary (P0); the
  absence of Approve/Reject on the self view is a softer authorization affordance (P2).
- **TC-508 → P3.** The period range + calendar is purely presentational and fully bypassed by the `‹`/`›`
  chevrons (already P1 in TC-002/003), so it is the lone nice-to-have.
