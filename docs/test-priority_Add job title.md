## Contested Calls

- **TC-102 → P0 not P1**: arguably "just validation", but uniqueness is the only
  invariant on this entity and the check is async/debounced — exactly the kind of UX
  that silently regresses (the padded-duplicate silent 422 we found live proves the
  failure mode is real).
- **TC-201 → P0 vs TC-204 → P1**: both security. TC-201 is access control (any ESS user,
  zero effort); TC-204 requires an admin to *inject* the payload — attacker must already
  hold the privileged role, so one notch down.
- **TC-004 → P1 not P0**: propagation failure would be release-blocking, but the FK
  wiring is core platform behavior with API-layer coverage in the same run; the E2E
  smoke is confirmatory rather than the sole guard.
- **TC-005 → P2 not P1**: file upload is the most mechanically fragile E2E here
  (chooser + fixture), and the business value of the attachment is low; cost/benefit
  puts it below the validation journey.
