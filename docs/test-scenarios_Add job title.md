# Test Scenarios: Add Job Title (`Admin → Job → Job Titles`)

> Feature: creating a Job Title record — list page `/admin/viewJobTitleList` +
> add form `/admin/saveJobTitle` — Admin-only configuration data that feeds PIM job
> details, Recruitment vacancies, and Performance KPIs.
> Source: `orangehrm-opensource-domain` (SKILL.md, business-rules.md §9/§11,
> api-reference.md Admin–Job Titles, ui-selectors.md Admin → Job → Job Titles)
> **plus live-app ground truth captured via Playwright MCP on the kord instance (2026-06-07)**.
> Generated by `create-scenarios` skill.

## Context & Verified Ground Truth (live app, Admin role)

- **List page** `/admin/viewJobTitleList`: `<h6>` "Job Titles", **Add** button,
  records counter `(6) Records Found`, table sorted **alphabetically by title (ASC)**
  (`GET /api/v2/admin/job-titles?limit=50&offset=0&sortField=jt.jobTitleName&sortOrder=ASC`).
  Columns: checkbox / Job Titles (sortable) / Job Description / Actions (**trash, pencil** — trash is FIRST).
  Long descriptions truncate at ~50 chars with a "Show More" toggle; short ones render fully.
- **Seeded titles (6, master data — do NOT mutate)**: Business Analyst, HR Specialist,
  QA Engineer, Senior Software Engineer, Software Engineer, UI Engineer.
- **Add form** `/admin/saveJobTitle`: `<h6>` "Add Job Title"; fields:
  - **Job Title*** — text input, required
  - **Job Description** — textarea, placeholder "Type description here"
  - **Job Specification** — file upload, helper text "Accepts up to 1MB"
  - **Note** — textarea, placeholder "Add note"
  - "* Required" legend, **Cancel** and **Save** buttons.
- **Validation (observed live)**:
  - Empty title + Save → inline `Required` under Job Title.
  - 120-char title → inline `Should not exceed 100 characters` **while typing** (live, not on save).
    ⚠ domain skill says "Should be less than N characters" — actual message differs; trust live text.
  - Duplicate title → inline `Already exists` — fires **live while typing** (async check) and is
    **case-insensitive** (`qa engineer` flagged against seeded `QA Engineer`).
- **⚠ Discovered behavior (potential app bug)**: a whitespace-padded duplicate
  (`"   QA Engineer   "`) **bypasses** the client-side duplicate check; the raw value is POSTed;
  backend rejects with **422 `{"error":{"status":"422","message":"Invalid Parameter","data":{"invalidParamKeys":["title"]}}}`**;
  the UI then **silently navigates back to the list with NO error toast** — the user gets no
  feedback that the save failed.
- **Happy path (verified)**: `POST /api/v2/admin/job-titles`
  body `{ "title": "...", "description": "", "specification": null, "note": "" }` → 200;
  UI redirects to `/admin/viewJobTitleList`; new row appears in its alphabetical slot;
  success toast (`.oxd-toast--success`) auto-dismisses in ~3s — assert it promptly or assert the row.
- **Delete (used for cleanup)**: trash icon → dialog "Are you Sure?" /
  "The selected record will be permanently deleted…" with **No, Cancel** / **Yes, Delete**.
  `DELETE /api/v2/admin/job-titles` body `{ "ids": [n] }`.
- Job titles are **hard-deleted** but deletion is blocked when referenced by an Employee or
  Vacancy: `"This record is in use and cannot be deleted"` (business-rules §11, api-reference 422).
- ESS users have no Admin menu at all (business-rules §2); admin endpoints return 403 for ESS sessions.

## Happy Path (TC-001–099)

### TC-001: Admin adds a job title with only the required field
**Category**: Happy Path
**Preconditions**: Logged in as Admin; title value is unique (timestamped test data).
**Steps**:
1. Navigate to Admin → Job → Job Titles → click **Add**.
2. Fill **Job Title** with a unique value; leave Description/Specification/Note empty.
3. Click **Save**.
**Expected Results**: Success toast (`.oxd-toast--success`); redirect to `/admin/viewJobTitleList`;
new row present; records count incremented by 1.
**Business Rule**: Only `title` is mandatory (`POST { title, description?, note?, specification? }`).
**Suggested Layer**: E2E

### TC-002: Admin adds a job title with all fields populated
**Category**: Happy Path
**Preconditions**: Admin; unique title.
**Steps**:
1. Open Add Job Title form.
2. Fill Job Title, Job Description, and Note (skip file upload).
3. Save.
**Expected Results**: Saved; list row shows the title and its description text.
API record carries `description` and `note` as submitted.
**Business Rule**: Optional fields persist verbatim.
**Suggested Layer**: E2E

### TC-003: New title lands in its alphabetical slot and count increments
**Category**: Happy Path
**Preconditions**: Admin; unique title chosen to sort mid-list (e.g. starting with "M").
**Steps**: Add the title; observe the list.
**Expected Results**: Default sort is `jobTitleName ASC` — the row appears in correct
alphabetical position; counter changes `(N)` → `(N+1) Records Found`.
**Business Rule**: List default sort `sortField=jt.jobTitleName&sortOrder=ASC` (verified).
**Suggested Layer**: E2E (assert within TC-001/002 run)

### TC-004: New job title is selectable in dependent modules
**Category**: Happy Path
**Preconditions**: A job title created in this session.
**Steps**: Open PIM → employee → Job tab (or Recruitment → Add Vacancy); open the
Job Title dropdown.
**Expected Results**: The newly created title is listed and selectable.
**Business Rule**: Vacancy/PIM reference job titles by FK; Recruitment requires the title
to pre-exist (business-rules §7).
**Suggested Layer**: API (GET list reflects new id) + one E2E smoke

### TC-005: Add a job title with a job specification file (≤ 1MB)
**Category**: Happy Path
**Preconditions**: Admin; a small PDF/DOC fixture file.
**Steps**: Fill title; attach file via Browse; Save.
**Expected Results**: Saved; record's `jobSpecification` is populated (API shows attachment id/filename).
**Business Rule**: "Accepts up to 1MB" (form helper text, verified).
**Suggested Layer**: E2E

### TC-006: Cancel abandons the form without creating a record
**Category**: Happy Path
**Preconditions**: Admin on Add form with a filled title.
**Steps**: Click **Cancel**.
**Expected Results**: Back on `/admin/viewJobTitleList`; record count unchanged; no new row.
**Business Rule**: Cancel is non-mutating.
**Suggested Layer**: E2E

## Business Rules (TC-100–199)

### TC-101: Job Title is required
**Category**: Business Rule
**Preconditions**: Admin on Add form.
**Steps**: Leave Job Title empty → click Save.
**Expected Results**: Inline `Required` under Job Title (verified live); no POST fired; stays on form.
**Business Rule**: Required-field validation (business-rules §9).
**Suggested Layer**: Component (E2E only as part of a combined validation test)

### TC-102: Duplicate title is rejected with live inline "Already exists"
**Category**: Business Rule
**Preconditions**: Seeded title `QA Engineer` exists.
**Steps**: Type `QA Engineer` into Job Title; pause for the async check.
**Expected Results**: Inline `Already exists` appears **before Save is clicked** (verified live).
Save with the error present must not create a duplicate.
**Business Rule**: Unique job title (business-rules §9 "Unique violations").
**Suggested Layer**: E2E

### TC-103: Duplicate check is case-insensitive
**Category**: Business Rule
**Preconditions**: `QA Engineer` exists.
**Steps**: Type `qa engineer`.
**Expected Results**: Inline `Already exists` (verified live).
**Business Rule**: Uniqueness compares case-insensitively.
**Suggested Layer**: E2E (same test as TC-102) / API

### TC-104: Title longer than 100 characters is blocked
**Category**: Business Rule
**Preconditions**: Admin on Add form.
**Steps**: Type a 120-char string into Job Title.
**Expected Results**: Inline `Should not exceed 100 characters` appears live (verified);
Save does not create the record.
**Business Rule**: Max title length = 100 (verified live; supersedes the generic skill wording).
**Suggested Layer**: Component / E2E (combined validation test)

### TC-105: Exactly 100 characters is accepted (boundary)
**Category**: Business Rule
**Preconditions**: Admin; unique 100-char title.
**Steps**: Enter a 100-char unique title → Save.
**Expected Results**: No length error; record created; full string displayed in the list row.
**Business Rule**: Boundary of the 100-char limit.
**Suggested Layer**: API (UI boundary smoke optional)

### TC-106: Job specification file over 1MB is rejected
**Category**: Business Rule
**Preconditions**: Admin; fixture file > 1MB.
**Steps**: Fill unique title; attach the oversized file; Save.
**Expected Results**: Inline/file error (helper says "Accepts up to 1MB"); record not created
with the attachment.
**Business Rule**: 1MB attachment cap (form helper, verified text).
**Suggested Layer**: E2E (file-chooser interaction is browser-level)

### TC-107: Job title in use cannot be deleted
**Category**: Business Rule
**Preconditions**: A job title assigned to an employee or vacancy.
**Steps**: From the list, trash that title → confirm.
**Expected Results**: Error toast `This record is in use and cannot be deleted`; row remains.
**Business Rule**: FK-protected hard delete (business-rules §11; api-reference 422 table).
**Suggested Layer**: API (E2E optional; adjacent to Add scope)

## Security (TC-200–299)

### TC-201: ESS user cannot reach the Add Job Title page
**Category**: Security
**Preconditions**: ESS user exists (no admin rights).
**Steps**:
1. Login as ESS — verify the Admin menu item is absent.
2. Navigate directly to `/web/index.php/admin/saveJobTitle` and `/admin/viewJobTitleList`.
**Expected Results**: No Admin menu; direct URLs render a forbidden/credential-error page or
redirect — the Add form is never shown.
**Business Rule**: Admin-only module (business-rules §2; Flow 9).
**Suggested Layer**: E2E

### TC-202: ESS session cannot create a job title via API
**Category**: Security
**Preconditions**: Valid ESS session cookie.
**Steps**: `POST /api/v2/admin/job-titles` with `{ "title": "Hacked Title" }` using the ESS session.
**Expected Results**: `403 Unauthorized`; no record created.
**Business Rule**: Data-group permission enforcement at API layer (Flow 9).
**Suggested Layer**: API

### TC-203: Unauthenticated access is redirected to login
**Category**: Security
**Preconditions**: No session (fresh context).
**Steps**: GET `/web/index.php/admin/saveJobTitle`.
**Expected Results**: Redirect to `/auth/login` (with `next` param per business-rules §1);
API POST without session → 401/302.
**Business Rule**: Session-gated UI (business-rules §1).
**Suggested Layer**: API + one E2E assertion

### TC-204: Script payload in title is stored inert (XSS)
**Category**: Security
**Preconditions**: Admin.
**Steps**: Create title `<img src=x onerror=alert(1)>-<ts>`; view the list page.
**Expected Results**: Payload rendered as escaped text in the row; no script execution
(no dialog; no console security errors). Cleanup: delete the record.
**Business Rule**: Output encoding on user-supplied strings.
**Suggested Layer**: E2E

### TC-205: SQL-metacharacter title is treated as plain data
**Category**: Security
**Preconditions**: Admin.
**Steps**: Create title `Robert'); DROP TABLE ohrm_job_title;-- <ts>` via API.
**Expected Results**: 200, stored verbatim; list still loads (no 500); other titles intact.
**Business Rule**: Parameterized persistence (Doctrine ORM).
**Suggested Layer**: API

## Negative / Error (TC-300–399)

### TC-301: Filled optional fields do not satisfy the required title
**Category**: Negative
**Preconditions**: Admin on Add form.
**Steps**: Fill Description + Note only → Save.
**Expected Results**: `Required` under Job Title; no record created.
**Business Rule**: Title is the only mandatory field — and it is genuinely mandatory.
**Suggested Layer**: Component / E2E (combined validation test)

### TC-302: Whitespace-only title is rejected
**Category**: Negative
**Preconditions**: Admin on Add form.
**Steps**: Enter `"   "` (spaces only) → Save.
**Expected Results**: Record is NOT created — either inline `Required` or backend 422.
(Not probed live; assert "no new record" rather than a specific message.)
**Business Rule**: Required ⇒ non-blank.
**Suggested Layer**: API

### TC-303: Whitespace-padded duplicate fails silently (documents app bug)
**Category**: Negative
**Preconditions**: `QA Engineer` exists.
**Steps**: Enter `"   QA Engineer   "` → no inline error appears (client check misses it) → Save.
**Expected Results (current behavior, verified)**: `POST` returns
**422 Invalid Parameter (invalidParamKeys: ["title"])**; UI navigates back to the list
with **no error toast**; record count unchanged.
**⚠ Expected per UX rules (business-rules §10)**: a red failure toast should appear —
current silent failure is a **potential app bug**; test pins the no-duplicate-created invariant.
**Business Rule**: Uniqueness enforced server-side after trim; every failed action should toast.
**Suggested Layer**: API (pin 422) + E2E note

### TC-304: API rejects >100-char title (server-side parity)
**Category**: Negative
**Preconditions**: Admin session.
**Steps**: `POST /api/v2/admin/job-titles` with a 101-char title (bypassing the UI).
**Expected Results**: `422 Invalid Parameter` with `invalidParamKeys: ["title"]`; no record.
**Business Rule**: Validation must not be client-only.
**Suggested Layer**: API

### TC-305: Duplicate POST via API is rejected
**Category**: Negative
**Preconditions**: `QA Engineer` exists.
**Steps**: `POST /api/v2/admin/job-titles` `{ "title": "QA Engineer" }`.
**Expected Results**: 422 (duplicate); list still contains exactly one `QA Engineer`.
**Business Rule**: Uniqueness at API layer.
**Suggested Layer**: API
