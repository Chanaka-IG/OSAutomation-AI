# Test Strategy: My Leave (ESS)

> Input: `docs/test-scenarios_My leave as ESS.md` (35 scenarios). Generated by `/test-strategy`. Consumed by `/define-priority`.
> Goal: assign each scenario to the lowest adequate layer (pyramid, not ice-cream-cone).
> Context: `/leave/viewMyLeaveList` is a read-and-act self-service grid. Day-count/balance/overlap logic lives **server-side** (PHP); the page itself is mostly search + table + row actions. No client-side pure logic and no component-test harness exist in this repo, so the realistic pyramid here is API (security + numeric assertions) at the base and E2E for the journeys.

## Layer Distribution
| Layer | Count | Focus | Approx. time |
|-------|-------|-------|--------------|
| Unit | 0 | No pure client-side logic exposed for this flow (balance/day-count computed server-side) | — |
| API | 4 | Cross-user access control + balance/escrow numeric assertions against `/api/v2/leave/leave-requests` & `leave-entitlements` | fast |
| Component | 0 | No component harness in this repo; grid/empty-state/loader rendering folded into E2E | — |
| E2E | 33 | The ESS self-service list journey: search/filter, status-required rule, cancel-own, self-scoping, UI state | slow |

> Defense-in-depth: TC-104 (cancel restores escrow) and TC-106 (balance column value) are validated at **both** API (deterministic numeric delta) and E2E (user action + on-screen value).

## API Assignments
| ID | Title | Endpoint / rationale |
|----|-------|----------------------|
| TC-104 | Escrow restored on cancel | `PUT /api/v2/leave/leave-requests/{id}` `{action:CANCEL}` then read balance via `GET /leave/leave-entitlements` / `leave-balance/{typeId}` — assert numeric delta deterministically |
| TC-106 | Balance value | `GET /leave/leave-balance/{leaveTypeId}?empNumber=self` — assert the number the grid renders |
| TC-204 | Cross-user read blocked | `GET /api/v2/leave/leave-requests?empNumber=<other>` → `403 Unauthorized` (access control belongs at API) |
| TC-205 | Cross-user action blocked | `PUT /api/v2/leave/leave-requests/{otherId}` `{action:CANCEL}` → `403`; target unchanged |

## Decision Rationale (contested)
- **TC-204 / TC-205 (cross-user access)** — authorization is a backend contract; testing it through the browser is slow and indirect (the UI simply omits the controls). Primary layer is **API**, asserting `403`. The UI-side of isolation (no employee selector) is still covered at E2E by TC-102/TC-202 for defense-in-depth.
- **TC-104 / TC-106 (balance)** — the *computation* is a backend rule → assert via **API balance delta** (deterministic, immune to grid-format drift). The *user-visible* value and the cancel *action* are genuinely full-stack → keep the **E2E** that performs the action and reads the column. Defense-in-depth.
- **TC-301 / TC-101 (status required)** — normally input-validation belongs below E2E, BUT this is a live-verified, page-specific mandatory-filter rule (`Show Leave with Status*`) with no API analogue on a read endpoint, and it gates every search. Kept at **E2E** as the primary (and only) layer.
- **TC-302 (From>To)** — date-picker range handling; low value and the picker typically prevents it. Kept as a single light **E2E** (no separate API), not release-gating.
- **TC-503 / TC-506 (loader / multi-select feedback)** — ideally component tests, but no component harness exists in this repo → folded into **E2E**, low priority.

## Anti-Patterns Checked (existing tests)
- Existing leave suites assert success via the **`.oxd-toast--success`** locator (not the page heading) and verify working-day/balance math via **API delta** — reuse both patterns here (consistent with `LeaveListPage` and the Assign/Apply suites).
- Avoid asserting cross-user authorization only through the browser — push it to the **API** layer (TC-204/205).
- Avoid an ice-cream-cone: the 33 E2E items are justified by this being a UI-centric self-service grid; the genuinely backend concerns (authz, balance numbers) are pushed down to the 4 API items.

## Layer Totals (for `/define-priority`)
- E2E: 33 · API: 4 · Component: 0 · Unit: 0 (TC-104, TC-106 counted in both E2E and API).
