# Test Scenarios — Performance → My Trackers

> **Feature**: Performance → **My Trackers** (ESS self-service view of Performance Trackers).
> **UI screen**: `viewMyPerformanceTrackerList` (Vue route `vueperformance.my_trackers_list`).
> **Generated by**: `/create-scenarios` — traced to `orangehrm-opensource-domain` skill + verified against `orangehrmPerformanceTrackerPlugin` source (schema, install.sql permissions, API endpoint validators).

## Feature Model (discovered from source)

A **Performance Tracker** (`ohrm_performance_track`) is created by Admin/Supervisor/HoD against a *subject employee* (`emp_number`). It has: `tracker_name` (≤200 chars, required), the subject Employee, a set of **Reviewers** (`ohrm_performance_tracker_reviewer`), and a set of **Logs** (`ohrm_performance_tracker_log`).

**My Trackers** is the ESS-facing screen: a logged-in employee sees **only the trackers where they are the subject** (`self = 1` data-group scope), reads the logs, sees a feedback summary, and can add/edit/delete **their own** logs.

A **Tracker Log** has:
- `log` — heading text, **required, max 150 chars** (API validator `getNonEmptyStringValidator(150)`)
- `comment` — **required, max 3000 chars** (`getNonEmptyStringValidator(3000)`)
- `performance` / `achievement` — **required**, FK to rating scale; seeded values: **`1` Positive** (green `#9cd318`), **`2` Development Needs** (red `#f21363`), **`3` General Comments** (grey `#cfd3de`)
- `visibleToEmployee` — boolean, default `true`
- `attachments` — 0–5 files (Enterprise)
- `reviewer_id` / `user_id` — attribution

### Permissions (from `dbscripts/install.sql`)
| Role | My Trackers data group | My Tracker Logs data group |
|------|------------------------|-----------------------------|
| ESS  | read-only, `self=1` (own trackers only) | full **CRUD**, `self=1` (own logs) |
| Admin | screen perm `(0,0,0,0)` → **no "My Trackers" menu** (uses *Employee Trackers* instead) | — |

### Open Source vs Enterprise note
Scenarios tagged **[Enterprise-conditional]** exercise capabilities that exist in the source tree but are gated to Enterprise/AI editions: per-log **visibility hiding** (`visibleToEmployee=false`), **attachments**, **AI log-heading generation**, **CSV export**. On an Open Source install the test-strategy step should skip or feature-detect these; all other scenarios are core Open Source behavior.

### Stable anchors
- My Trackers list API: `GET /api/v2/performance/trackers?empNumber=<self>` (UI) — endpoint `GET /api/performance-trackers`
- Logs: `GET|POST|DELETE /api/performance-trackers/:trackerId/logs`, `GET|PATCH /api/performance-trackers/:trackerId/logs/:id`

## Happy Path (TC-001–099)

### TC-001: ESS views the My Trackers list
**Category**: Happy Path
**Preconditions**: ESS user logged in; at least one tracker exists where this user is the subject.
**Steps**:
1. Login as the ESS user.
2. Navigate to `Performance → My Trackers`.
**Expected Results**: List renders the user's tracker(s); each row/card shows tracker name, added date, modified date, and reviewer(s). No trackers belonging to other employees appear.
**Business Rule**: My Trackers data group is `self=1`, read-only — employee sees only trackers where `emp_number` = self.
**Suggested Layer**: E2E

## Security (TC-200–299)

### TC-200: ESS cannot open another employee's tracker by id
**Category**: Security
**Preconditions**: Tracker T belongs to employee B; login as employee A.
**Steps**: Navigate / `GET /api/performance-trackers/{T}` as A.
**Expected Results**: `403 Unauthorized`; no tracker data leaked.
**Business Rule**: Self-scope enforcement on tracker access.
**Suggested Layer**: API

### TC-201: ESS cannot read another employee's tracker logs
**Category**: Security
**Preconditions**: As TC-200.
**Steps**: `GET /api/performance-trackers/{T}/logs` as A.
**Expected Results**: `403 Unauthorized`; zero logs returned.
**Business Rule**: `isPermittedForAction` / accessible-id filter on logs.
**Suggested Layer**: API

### TC-202: ESS cannot add a log to a tracker they don't own
**Category**: Security
**Preconditions**: As TC-200.
**Steps**: `POST /api/performance-trackers/{T}/logs` with valid body as A.
**Expected Results**: `403 Forbidden`; no log created.
**Business Rule**: Create permission scoped to own tracker.
**Suggested Layer**: API

### TC-203: ESS cannot delete another employee's log
**Category**: Security
**Preconditions**: Log L on tracker T owned by B; login as A.
**Steps**: `DELETE /api/performance-trackers/{T}/logs` with `ids:[L]` as A.
**Expected Results**: Rejected/no-op; `L` not in A's accessible delete ids → `403`/empty delete.
**Business Rule**: `getAccessibleLogIdsPerAction(...DELETE)` ∩ ids.
**Suggested Layer**: API

### TC-204: ESS cannot edit a log on a tracker they don't own
**Category**: Security
**Preconditions**: As TC-203.
**Steps**: `PATCH /api/performance-trackers/{T}/logs/{L}` as A.
**Expected Results**: `403 Forbidden`.
**Business Rule**: Update scoped via accessible-id filter.
**Suggested Layer**: API

### TC-205: Deep link to My Trackers when logged out redirects to login
**Category**: Security
**Preconditions**: No active session.
**Steps**: Open `/performance/myPerformanceTrackerList` directly.
**Expected Results**: Redirect to `/auth/login?next=...`.
**Business Rule**: Session enforcement on all deep links.
**Suggested Layer**: E2E

### TC-206: ESS cannot reach the Admin "Employee Trackers" screen
**Category**: Security
**Preconditions**: ESS logged in.
**Steps**: Open `/performance/viewEmployeePerformanceTrackerList` directly; `GET /api/performance-trackers` (admin list) as ESS.
**Expected Results**: Forbidden / empty; the admin Performance Trackers list is not accessible to ESS.
**Business Rule**: `performance_trackers` data group not granted to ESS.
**Suggested Layer**: API + E2E

### TC-207: Hidden log not leaked via field/relation selection [Enterprise-conditional]
**Category**: Security
**Preconditions**: Tracker with a `visibleToEmployee=false` log; login as subject.
**Steps**: Request logs with `fields=...`/`include=...` permutations as the employee.
**Expected Results**: Hidden log never returned regardless of field/include params.
**Business Rule**: Visibility filter applied server-side, not via field projection.
**Suggested Layer**: API

### TC-208: CSRF token required for log create/delete (cookie flow)
**Category**: Security
**Preconditions**: Valid ESS session cookie.
**Steps**: `POST`/`DELETE` a log omitting / using a stale `X-CSRF-Token`.
**Expected Results**: `401 Invalid CSRF token`.

**Suggested Layer**: API

### TC-209: Attachment download scoped to the owning tracker [Enterprise-conditional]
