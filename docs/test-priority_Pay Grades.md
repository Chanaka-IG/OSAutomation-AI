## Contested Calls

- **TC-102 → P0 not P1**: arguably "just validation", but uniqueness is a core invariant on this
  entity and the check is async/debounced — exactly the kind of UX that silently regresses.
- **TC-003 → P1 not P0**: currency add is the feature's reason to exist, but a pay grade can be
  created and referenced without a currency band, and the create flow (TC-001) is the harder gate;
  so high-impact rather than release-blocking.
- **TC-105 → P1 not P2**: it is "just validation", but an inverted salary band is a data-integrity
  defect feeding downstream salary records, which lifts it above ordinary field validation.
- **TC-201 → P0 vs TC-204 → P1**: both security. TC-201 is access control (any ESS user, zero
  effort); TC-204 requires an admin to inject the payload — the attacker already holds the
  privileged role, so one notch down.
- **TC-106 → P2 not P1**: the dropdown-exclusion UX is a pleasant guard, but duplicate currencies
  are independently prevented server-side; losing the exclusion is a degraded-UX bug, not a
  release blocker.
