## Issues Found

### [IMPORTANT] Hardcoded hour values in test bodies
- **Lines** ~175–176 (TC-005 expected `'08:00'`), 209–210 (TC-008 `'08:00'`/`'04:00'`),
  229–230 & 234 & 237 (TC-009 `'08:00'`/`'04:00'`/`'12:00'`), 259 (TC-103 `'08:30'`).
- **Current:** durations and expected totals are inline string literals.
- **Rule violated:** best-practices §5 "Pass data to Page class from test body" + §8 "Unique/maintainable
  test data" — sample values should come from `test-data`, not be sprinkled as magic strings.
- **Fix:** extend `timesheets.samples` with the multi-day set and the alternate HH:MM value, e.g.
  ```ts
  samples: {
    // …
    multiDay: { day1: '08:00', day2: '04:00', total: '12:00' },
    hhmmAlt: '08:30',
  }
  ```
  and reference `tsData.samples.multiDay.day1`, `.total`, `tsData.samples.hhmmAlt` in TC-005/008/009/103.
  (TC-005's *input* already uses `tsData.samples.validHours`; align its expected value to the same source.)

### [IMPORTANT] TC-008 delete assertion is row-order dependent
- **Line** 220: `expect(entries.data[0].activity.name).toBe(tsData.samples.activityName2)`.
- **Current:** assumes the seeded "Development" row renders/persists first so `deleteFirstRow()` removes it,
  leaving "Testing". If the entries order ever differs, the wrong row is deleted and the assertion still
  *might* pass/fail misleadingly.
- **Rule violated:** best-practices §11 "Order-dependent failures / test user-visible behavior".
- **Fix:** assert by absence/presence rather than position:
  ```ts
  const names = entries.data.map((e) => e.activity.name);
  expect(names).toHaveLength(1);
  expect(names).not.toContain(tsData.samples.activityName);   // deleted one is gone
  expect(names).toContain(tsData.samples.activityName2);      // survivor remains
  ```

### [SUGGESTION] `statusText` locator uses tag+text instead of a role/text query
- **File** `MyTimesheetPage.ts`: `this.statusText = page.locator('p').filter({ hasText: 'Status:' })`.
- **Rule:** best-practices §2 locator priority (prefer `getByText`/role over raw tag selectors).
- **Fix:** `this.statusText = page.getByText(/^Status:/)` (or scope to the timesheet card) — more
  resilient if the element tag changes.

### [SUGGESTION] `gridRows` includes the `--total` footer row
- **File** `MyTimesheetPage.ts`: `gridRows = page.locator('.orangehrm-timesheet-table-body-row')` also
  matches the totals row, so `gridRowByText('Total')` would be ambiguous (harmless today, but a trap).
- **Fix:** exclude the footer for entry rows:
  `page.locator('.orangehrm-timesheet-table-body-row:not(.\\--total)')`, and keep `grandTotalRow`
  pinned to `…--total`.

### [SUGGESTION] Date helper duplication
- **Spec** `addDaysStr` (lines ~30–34) duplicates `TimesheetsApi.addDays`.
- **Fix:** export a single date util (e.g. from a small `src/lib/date.ts`) and reuse in both, or call the
  API helper's method, to keep one source of truth (best-practices §5 maintainability).

### [SUGGESTION] IDOR assertion could be stronger
- **Line** ~344 (TC-202): asserts only `editHeading.toHaveCount(0)` for the ESS user.
- **Fix:** additionally assert the page did not land on a populated edit form for another employee, e.g.
  `await expect(page).not.toHaveURL(/editTimesheet/)` *or* assert a forbidden/redirect indicator, to make
  the security intent explicit (best-practices §4 URL assertions).

### [SUGGESTION] `afterAll` cleanup logs HTTP 400 (non-fatal)
- Projects/customers seeded for the suite are referenced by timesheet entries (timesheets are not
  deletable), so `deleteProjects`/`deleteCustomers` return 400 and `TimeProjectsApi` warns.
- **Fix:** either document this as expected (one comment in `afterAll`) or soft-skip the delete when the
  project has entries, so the logs don't read as a real failure. No test impact.

### [SUGGESTION] `findEmptyWeek` scan cost grows across runs
- Each full run consumes ~7 past weeks; over many runs the backward scan from `today-120d` lengthens.
- **Fix:** acceptable as-is (`maxWeeksBack=520` ≈ 10 yrs). Optionally start the cursor further back or key
  the base date off a per-run offset. Note-only.
