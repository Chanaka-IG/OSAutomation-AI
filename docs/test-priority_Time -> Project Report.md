# Test Priority — Time → Project Report

> Input: `docs/test-strategy_Time -> Project Report.md`. Feature: **Time → Reports → Project Report**.
> Scope: **E2E scenarios only** (API-primary TC-101/102/103/105/106/202/203/304/401/402/404 owned by the API layer).
> Generated by `/define-priority`. Consumed by `/generate-tests`.

Priority key: **P0** release-blocking · **P1** high impact · **P2** moderate · **P3** low/cosmetic.

---

## P0 — Release-blocking (core flow, data integrity, security, no workaround)

| ID | Scenario | Rationale |
|---|---|---|
| TC-001 | Generate a project report for a project with logged time | The reason the feature exists — select a project, View, get the activity/hours table. If this fails the feature is dead. No workaround. |
| TC-003 | Total Duration equals the sum of activity rows | The report's headline number; a wrong total is a data-integrity defect that misinforms billing/effort decisions. |
| TC-200 | Unauthenticated access redirects to login | Security baseline — timesheet/effort data must not be reachable without a session. |

## P1 — High impact (primary feature paths, primary filters, validation, core states)

| ID | Scenario | Rationale |
|---|---|---|
| TC-002 | Columns are "Activity Name" / "Time (Hours)" | The core read surface; the report is meaningless without its two columns. |
| TC-005 | Project Name autocomplete lists "Customer - Project" | The autocomplete is the *only* way to choose the mandatory project — the entry control to the whole flow. |
| TC-006 | Generate a report filtered by a date range | A primary filter; period-scoped reporting is a headline use case. |
| TC-007 | "Only Include Approved Timesheets" narrows the totals | Primary filter that changes the reported numbers (verified 96.00→48.00); high impact on correctness. |
| TC-004 | Drill down from an activity into the Activity Details report | The primary secondary-navigation feature — per-employee breakdown is a key reason to use the report. |
| TC-104 | Drill-down breaks the activity total down per employee | Confirms the drill-down shows the *right* numbers (reconciles to the parent activity total). |
| TC-100 | Project Name is required | The mandatory-field guard gating the entire report; primary validation. |
| TC-502 | Empty result shows "No Records Found" | A very common report state (projects with no qualifying time); users must see a clear empty state, not a blank/broken table. |
| TC-503 | "(N) Record(s) Found" matches the row count | Count integrity — the header must agree with the rendered rows. |
| TC-504 | Total Duration footer is always present after View | The footer is the report's summary line; must render for both data and empty results. |

### Notes for generation
- Add a `src/pages/time/ProjectReportPage.ts` covering: expanding the **Project Report** criteria card
  (header toggle `button.oxd-icon-button` with `i.bi-caret-down-fill`), the **Project Name** autocomplete
  (`Type for hints...`, options `Customer - Project`), **From/To** date pickers, the **Only Include Approved
  Timesheets** toggle, the **View** button (`button.oxd-button--secondary`), the results table
  (Activity Name / Time (Hours)), `(N) Record(s) Found`, the `Total Duration (Hours): X.XX` footer, and the
  activity drill-down link → `/time/displayProjectActivityDetailsReport`.
- **Data backbone:** the report reads aggregated timesheet hours, so a deterministic dataset must exist. Seed
  via API in `beforeAll` using `TimeProjectsApi` (project + customer + activity) and `TimesheetsApi`
  (create week → fill rows → **submit + approve** some, leave some submitted) so `all` > `onlyApproved` is
  deterministic. Use **unique names** (`Date.now()`) and **hard-delete** seeded projects/customers in `afterAll`.
- **Never assert absolute totals** against pre-existing instance data (15 projects already carry assorted
  hours). Assert the **delta** the test created, or target a **known seeded project** by id/name.
- TC-200 uses a no-session context (fresh `request`/incognito) → expect redirect to `/auth/login`.
- Verify the exact "Required" copy and the drill-down "--" employee rendering live during generation.
