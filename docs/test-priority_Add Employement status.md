## Contested Calls

- **TC-102 → P0 not P1**: arguably "just validation", but uniqueness is a core invariant on this
  entity and the check is async/debounced — exactly the kind of UX that silently regresses and lets
  a duplicate status into the Job-Details dropdown.
- **TC-100+ → P1 not P0**: required/length validation protects data quality, but a single bad input
  is recoverable and does not block the whole feature the way a broken create (TC-001) does; so
  high-impact rather than release-blocking.
- **TC-201 → P0 vs TC-204 → P1**: both security. TC-201 is access control (any ESS user, zero
  effort); TC-204 requires an admin to inject the payload — the attacker already holds the
  privileged role, so one notch down.
- **TC-003 → P2 not P1**: rename is a real path but lower reach than create; delete-and-recreate is a
  trivial workaround, so moderate.
- **TC-505 → P2 not P3**: the delete dialog is cleanup-adjacent, but it guards an irreversible
  hard-delete with a confirmation step — worth a named assertion above cosmetic.
