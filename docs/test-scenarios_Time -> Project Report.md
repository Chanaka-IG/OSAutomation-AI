## Feature Reference (verified live, 2026-06-18)

### Routes
| Route | Purpose |
|---|---|
| `/web/index.php/time/displayProjectReportCriteria` | Project Report **criteria form** + rendered results (same page). Heading "Project Report" (`<h5>`). |
| `/web/index.php/time/displayProjectActivityDetailsReport?fromDate=&toDate=&projectId=&activityId=&includeTimesheet=` | **Drill-down** Activity Details report (time per employee for one activity). |

### Criteria form (collapsible card "Project Report")
- The card is **collapsed by default**; a header toggle (`button.oxd-icon-button` with `i.bi-caret-down-fill` / `bi-caret-up-fill`) expands/collapses the criteria.
- **Project Name\*** — autocomplete (`Type for hints...`). Options are formatted **`Customer - Project`** (e.g. `ETS Customer - ETS Project`). **Required.**
- **Project Date Range** — **From** / **To** date pickers (`textbox "From"` / `textbox "To"`, calendar icon). Optional.
- **Only Include Approved Timesheets** — OXD toggle/checkbox, **default OFF**.
- **\* Required** legend + **View** button (`button.oxd-button--secondary`, green, `type="submit"`).

### Report results (rendered below the criteria after **View**)
- Results card header: **`(N) Record(s) Found`** + a fullscreen/expand icon.
- Columns: **Activity Name** | **Time (Hours)**.
- **Activity Name** is a **drill-down link** → `/time/displayProjectActivityDetailsReport?...&projectId=&activityId=&includeTimesheet=`.
- Footer: **`Total Duration (Hours): X.XX`** (equals `meta.sum.label`).
- Empty result → **`No Records Found`**, `Total Duration (Hours): 0.00`.

### Drill-down — Activity Details Report
- Columns: **Employee Name** | **Time (Hours)**; same `(N) Record(s) Found` + Total Duration footer.
- Employee Name shows **`--`** when the employee name is unavailable (e.g. purged/blank).

### API contract (verified)
| Method | Endpoint | Body / Result |
|---|---|---|
| GET | `/api/v2/time/reports?name=project` | Report **definition**: `data.headers=[{name:"Activity Name",prop:"activityName"},{name:"Time (Hours)",prop:"time"}]`, `data.filters=[]` |
| GET | `/api/v2/time/reports/data?limit=50&offset=0&projectId={id}&includeTimesheet=all\|onlyApproved&fromDate=&toDate=&name=project&_dateFormattingEnabled=true` | `{ data:[{ activityId, activityName, deleted, time:"HH.dd", _url:{activityName:"/time/displayProjectActivityDetailsReport?..."} }], meta:{ total, sum:{hours,minutes,label}, project:{id,name,description,deleted} } }` |
| GET | `/api/v2/time/projects?onlyAllowed=true&model=detailed&customerOrProjectName={q}` | Autocomplete source for Project Name |

### Behaviour (verified)
- **Project Name is mandatory**: clicking **View** with no project shows inline **"Required"**; no report renders.
- **Only Include Approved Timesheets** toggles the `includeTimesheet` param: **OFF → `all`** (SUBMITTED + APPROVED hours), **ON → `onlyApproved`** (APPROVED only). Verified: same project returned **96.00** (`all`) vs **48.00** (`onlyApproved`). Matches domain `business-rules.md` §6 — *only `SUBMITTED` and `APPROVED` count toward project/activity reports*.
- **Project Date Range** filters timesheet entry dates: a future window (`2030-01-01..2030-12-31`) returned **0 rows / 0.00**; a broad past window returned the full **96.00**.
- The report **aggregates hours per activity** for the selected project across all employees; **Total Duration** = the sum across activity rows.
- Selecting a project then **View** is the core flow; the drill-down opens a per-employee breakdown for a single activity.

## TC-001–099 — Happy Path

### TC-001: Generate a project report for a project with logged time
**Category**: Happy Path
**Preconditions**: Admin logged in; a project with submitted/approved timesheet hours exists (e.g. `ETS Project`).
**Steps**: Open Project Report → expand criteria → select the project in Project Name → click **View**.
**Expected Results**: Results card shows `(N) Record(s) Found`, one row per activity with **Activity Name** + **Time (Hours)**, and **Total Duration (Hours)** equal to the sum of the rows.
**Business Rule**: Report aggregates timesheet hours per activity per project.
**Suggested Layer**: E2E

### TC-002: Report columns are "Activity Name" and "Time (Hours)"
**Category**: Happy Path
**Preconditions**: A report has been generated.
**Steps**: Inspect the results table header.
**Expected Results**: Exactly two columns — **Activity Name** and **Time (Hours)** — per the report definition (`/time/reports?name=project`).
**Business Rule**: Fixed report column set.
**Suggested Layer**: E2E / API

### TC-003: Total Duration equals the sum of activity rows
**Category**: Happy Path
**Preconditions**: A multi-activity project exists (e.g. project id 20 → 2 activities).
**Steps**: Generate the report.
**Expected Results**: `Total Duration (Hours): X.XX` equals the arithmetic sum of all **Time (Hours)** rows (= `meta.sum.label`).
**Business Rule**: Footer total = Σ activity hours.
**Suggested Layer**: E2E / API

### TC-004: Drill down from an activity into the Activity Details report
**Category**: Happy Path
**Preconditions**: A generated report with at least one activity row.
**Steps**: Click an **Activity Name** link.
**Expected Results**: Navigates to `/time/displayProjectActivityDetailsReport?...&projectId=&activityId=&includeTimesheet=`; table shows **Employee Name** + **Time (Hours)** and a Total Duration footer.
**Business Rule**: Activity drill-down = per-employee breakdown.
**Suggested Layer**: E2E

### TC-005: Project Name autocomplete lists "Customer - Project" options
**Category**: Happy Path
**Preconditions**: ≥1 project exists.
**Steps**: Expand criteria, type a fragment of a project name in Project Name.
**Expected Results**: A listbox of matching options formatted `Customer - Project`; selecting one fills the field.
**Business Rule**: Project picker is customer-scoped autocomplete.
**Suggested Layer**: E2E

### TC-006: Generate a report filtered by a date range
**Category**: Happy Path
**Preconditions**: A project with time logged in a known period.
**Steps**: Select project, set From/To covering the logged period, View.
**Expected Results**: Report shows only activities/hours whose timesheet dates fall in `[From, To]`.
**Business Rule**: Date range filters by timesheet entry date.
**Suggested Layer**: E2E / API

### TC-007: "Only Include Approved Timesheets" narrows the totals
**Category**: Happy Path
**Preconditions**: A project that has both approved and merely-submitted hours (e.g. `ETS Project`: all=96.00, approved=48.00).
**Steps**: Generate the report once with the toggle OFF, once ON.
**Expected Results**: ON yields hours ≤ OFF (approved-only subset); verified 48.00 (ON) vs 96.00 (OFF).
**Business Rule**: `onlyApproved` excludes non-approved (submitted) entries.
**Suggested Layer**: E2E / API

### TC-008: Criteria card collapses/expands via the header toggle
**Category**: Happy Path
**Steps**: Click the card header caret to expand, then collapse.
**Expected Results**: The criteria fields show then hide; toggle icon flips (`caret-down`↔`caret-up`).
**Business Rule**: Collapsible criteria panel.
**Suggested Layer**: E2E

## TC-100–199 — Business Rules

### TC-100: Project Name is required
**Category**: Business Rule
**Steps**: Expand criteria, leave Project Name empty, click View.
**Expected Results**: Inline **"Required"** under Project Name; no report renders; URL unchanged.
**Business Rule**: Project is the mandatory report key.
**Suggested Layer**: E2E

### TC-101: Only SUBMITTED + APPROVED hours count when toggle is OFF
**Category**: Business Rule
**Preconditions**: A project with NOT_SUBMITTED, SUBMITTED and APPROVED timesheet rows.
**Steps**: Generate the report with the approved toggle OFF (`includeTimesheet=all`).
**Expected Results**: Totals include SUBMITTED + APPROVED only; NOT_SUBMITTED hours are excluded.
**Business Rule**: `business-rules.md` §6 — only SUBMITTED/APPROVED count toward project reports.
**Suggested Layer**: API

### TC-102: Approved-only totals exclude submitted-but-unapproved hours
**Category**: Business Rule
**Steps**: Compare `includeTimesheet=all` vs `onlyApproved` for the same project.
**Expected Results**: `onlyApproved` ≤ `all`; the difference equals the non-approved submitted hours.
**Business Rule**: Approval state filtering.
**Suggested Layer**: API

### TC-103: Hours are aggregated per activity (one row per activity)
**Category**: Business Rule
**Preconditions**: Multiple employees logged time against the same activity of a project.
**Steps**: Generate the report.
**Expected Results**: One row per distinct activity; the row's hours = sum across all employees for that activity.
**Business Rule**: Activity-level aggregation across employees.
**Suggested Layer**: API

### TC-104: Drill-down breaks the activity total down per employee
**Category**: Business Rule
**Steps**: Note an activity's Time (Hours), then open its drill-down.
**Expected Results**: The sum of the drill-down **Employee Name** rows equals the activity's hours in the parent report.
**Business Rule**: Parent total = Σ per-employee hours.
**Suggested Layer**: E2E / API

### TC-105: Date range + approved toggle compose (both applied)
**Category**: Business Rule
**Steps**: Set a date range AND turn the approved toggle ON; View.
**Expected Results**: Result reflects approved entries within the range only (both filters intersect).
**Business Rule**: Filters are conjunctive.
**Suggested Layer**: API

### TC-106: Report is read-only (no data mutation)
**Category**: Business Rule
**Steps**: Generate a report; re-check the underlying timesheets.
**Expected Results**: No timesheet/activity records are modified; the screen only reads (`GET` only).
**Business Rule**: Reporting is non-mutating.
**Suggested Layer**: API

**Category**: Security

**Expected Results**: Redirect to `/auth/login`; no report.
**Business Rule**: Authenticated routes only.
**Suggested Layer**: E2E

### TC-201: ESS user access to Project Report is governed by Time data-group rights
**Category**: Security
**Preconditions**: ESS-only user logged in.
**Steps**: Navigate to `/time/displayProjectReportCriteria`.
**Expected Results**: Either "Credential Required" / no access, OR a scoped report per the role's Time permissions — verify the live outcome and assert it consistently (no privilege escalation).
**Business Rule**: Reports gated by Time data-group permissions.
**Suggested Layer**: E2E

### TC-202: Report data API rejects an unauthenticated/forbidden caller
**Category**: Security
**Steps**: Call `/api/v2/time/reports/data?...&name=project` without a valid session.
**Expected Results**: 401/403 (or redirect); no report data returned.
**Business Rule**: Server-side authorization on the report endpoint.
**Suggested Layer**: API

### TC-203: Tampered projectId cannot expose an unauthorized project
**Category**: Security
**Steps**: As a restricted user, request the data API with a projectId outside the allowed set (`onlyAllowed` excludes it).
**Expected Results**: Empty/forbidden — no hours for a project the user may not see.
**Business Rule**: `onlyAllowed` scoping is enforced server-side.
**Suggested Layer**: API
