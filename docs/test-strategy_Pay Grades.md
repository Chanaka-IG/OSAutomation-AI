## Context

Pay Grades is a **two-step CRUD feature feeding salary master data** to PIM. Unlike Job
Titles, its risk surface has two distinct shapes:

1. **The pay-grade record itself** — a single `Name` field with live async validation
   (`Required`, `Already exists`, `Should not exceed 50 characters` — all fire while typing),
   mirrored server-side by `POST /api/v2/admin/pay-grades { name }` → 422 on violation.
2. **The nested Currencies sub-grid** on the edit page — a `Currency*` dropdown plus optional
   `Minimum/Maximum Salary`, with a **cross-field min/max rule** (`Should be lower/higher than…`)
   and a **uniqueness-by-exclusion** behavior (an assigned currency is removed from the dropdown).

Two flows make this feature E2E-heavy relative to Job Titles: the **Save → redirect-to-edit**
choreography (Save does **not** return to the list — it opens `/admin/payGrade/{id}`), and the
**currency band UX**, which only exists in the browser. The currencies sub-resource and the
record-level contracts are cheap and deterministic at the **API layer**.

No Unit/Component layers — deployed black-box app, OXD components are upstream-tested (same
rationale as the Job Title, Dashboard, and Leave strategies). Component-ish scenarios
(TC-101/103/503/108) fold into combined E2E validation journeys rather than standing up a
component harness.

**Framework note**: `PayGradesApi` already exists (`getAll`, `create`, `createIfAbsent`) but has
**no `delete` and no currency methods**. Add `deleteByIds(ids: number[])` (DELETE
`/api/v2/admin/pay-grades { ids }`) for cleanup, and — if API-layer currency tests are kept —
a `createCurrency(payGradeId, {currencyId, minSalary?, maxSalary?})` against
`/api/v2/admin/pay-grades/{id}/currencies`. The 3 seeded grades (`Band A — Associate`, etc.)
are **master data** verified by `tests/setup`; tests must create their own timestamped grades
(`MPG-<ts>`) and clean up — never mutate the seeded three.

## Contested Assignments — Rationale

- **TC-102 stays E2E** even though uniqueness is also API-tested (TC-305): the live, debounced,
  pre-save inline `Already exists` is frontend behavior with real flake potential — exactly what
  a regression breaks, and unseeable at the API layer.
- **TC-103/304 (length boundary) split**: the UI message (`Should not exceed 50 characters`) is
  asserted once in the combined validation test; the exact 50/51 boundary is a server contract
  (TC-104 = 50 ok, TC-304 = 51 → 422). Note the **50-char** limit, not Job Titles' 100.
- **TC-105 (min/max) stays E2E**: the dual cross-field error is rendered UX. A server-side parity
  check could be added at the currency API if `createCurrency` lands, but the primary value is the
  browser validation.
- **TC-106 (currency exclusion) is E2E-only**: "the option disappears from the dropdown" is a
  rendered-list assertion with no API equivalent (the API would simply reject a duplicate POST).
- **TC-007 (propagation to PIM salary) deferred to a single optional smoke**: Pay Grade only
  surfaces in PIM → employee → Salary, which requires an employee fixture; lower impact than the
  Job-Title→Vacancy propagation. Kept as an optional cross-module smoke, not a release gate.
- **TC-204 (XSS) stays E2E**: "stored inert" is only provable in a rendering DOM.

## Anti-Patterns Found in Existing Tests / Avoided Here

- `PayGradesApi` has **no delete** method — add `deleteByIds(ids)` rather than cleaning up via the
  UI in every test (UI delete belongs to exactly one test: TC-505).
- `tests/setup` seeds the 3 pay grades via `createIfAbsent`; new tests must NOT delete or rename
  those seeded grades — use timestamped names (`MPG-<ts>`) and dedicated cleanup.
- Assert success via `.oxd-toast--success` (or the resulting row/redirect), never the page heading
  (project memory). **Beware the edit page's Info toast `No Records Found`** — it is
  `.oxd-toast--info`, not success; do not match it with a generic `.oxd-toast` selector.
- The Add flow **redirects to the edit page, not the list** — older "assert back on list URL"
  patterns from Job Titles do **not** apply to the create step here.
