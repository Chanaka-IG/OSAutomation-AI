# Test Priority — Attendance → Employee Records

> Input: `docs/test-strategy_Attendance -> Employee records.md`.
> Scope: **E2E scenarios only** (API-primary TC-102/103/104/105/204/400/401/405 are owned by the API layer).
> Generated by `/define-priority`. Consumed by `/generate-tests`.

Priority key: **P0** release-blocking · **P1** high impact · **P2** moderate · **P3** low/cosmetic.

---

## P0 — Release-blocking (core flow, security, data integrity, no workaround)

| ID | Scenario | Rationale |
|---|---|---|
| TC-001 | Summary lists employees with their total duration | The page's primary purpose; if the roster/totals don't load, the feature is dead on arrival. |
| TC-004 | Row "View" drills into the employee's detail | The core navigation — without it an admin can't reach any employee's records. No workaround. |
| TC-006 | Detail view lists the employee's punch records | The actual data an admin came to see; the payoff of the whole flow. |
| TC-200 | ESS user cannot access Employee Records | Privacy/compliance — an employee must not see the whole company's attendance. |
| TC-203 | Unauthenticated access redirects to login | Security baseline for the route. |

## P1 — High impact (primary path, security, high reach)

| ID | Scenario | Rationale |
|---|---|---|
| TC-002 | Filter the summary by date | The summary's main control; admins review specific days. |
| TC-005 | Select employee in filter + View → detail | Primary alternate path to a single employee's detail. |
| TC-007 | "(N) Records Found" equals the employee count | Data integrity of the roster count. |
| TC-003 | Summary row shows Name / Total / View | Primary read surface of the summary. |
| TC-201 | ESS cannot deep-link into an employee's detail | Direct-URL privilege escalation guard — high security value. |
| TC-202 | No edit/delete affordance when config OFF | Authorization affordance on the default install. |
| TC-300 | Empty Date + View → "Required" | Common validation path on the required control. |
| TC-302 | No-records employee → detail empty state | Common state (most employees/most days are empty); must render cleanly. |

## P2 — Moderate (secondary flows, edge-on-common-path, overlaps a P0/P1)

| ID | Scenario | Rationale |
|---|---|---|
| TC-100 | Date required (business-rule view) | Overlaps TC-300; moderate. |
| TC-101 | Employee Name filter optional | Reinforces default summary behaviour. |
| TC-106 | Default date = today | Overlaps TC-001; moderate. |
| TC-301 | Malformed date rejected | Field validation edge. |
| TC-303 | Non-existent employeeId deep-link | Robustness; uncommon. |
| TC-402 | Mixed-timezone GMT labels (detail) | Display correctness for an uncommon mix. |
| TC-404 | Deep-link to a detail URL | Direct navigation path. |
| TC-500 | Filter panel toggles | Secondary UI interaction. |
| TC-504 | Summary column labels | Display detail. |
| TC-505 | Detail column labels | Display detail. |

## P3 — Low / cosmetic
