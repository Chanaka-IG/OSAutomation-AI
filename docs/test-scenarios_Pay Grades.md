# Test Scenarios: Pay Grades (`Admin → Job → Pay Grades`)

> Feature: managing Pay Grade records — list page `/admin/viewPayGrades`, add form
> `/admin/payGrade`, and the **two-step** edit page `/admin/payGrade/{id}` that hosts a
> nested **Currencies** sub-grid (Currency + Minimum/Maximum Salary). Admin-only configuration
> data that feeds PIM job/salary details.
> Source: `orangehrm-opensource-domain` (SKILL.md, business-rules.md §9/§10/§11,
> api-reference.md Admin–Pay Grades, ui-selectors.md Admin patterns) **plus live-app ground
> truth captured via Playwright MCP on the kord instance (2026-06-08)**.
> Generated by `create-scenarios` skill.

## Context & Verified Ground Truth (live app, Admin role)

### List page `/admin/viewPayGrades`
- `<h6>` **"Pay Grades"**, **Add** button, records counter **`(3) Records Found`**.
- Table columns: checkbox / **Name** / **Currency** / **Actions**.
  Row action icons: **trash FIRST, then pencil-fill** (delete before edit — same order as Job Titles).
- The **Currency** column is blank for a grade that has no currencies assigned.
- List load: `GET /api/v2/admin/pay-grades?limit=50&offset=0` → 200.
- **Seeded grades (3, master data — do NOT mutate)**: `Band A — Associate`,
  `Band B — Professional`, `Band C — Lead / Principal` (all with no currency rows).

### Add form `/admin/payGrade`
- `<h6>` **"Add Pay Grade"**; a **single field**: **Name\*** (text, required).
- "* Required" legend, **Cancel** and **Save** buttons. No `maxlength` attribute on the input.
- **Validation (observed live)**:
  - Empty Name + Save → inline **`Required`** under Name; no POST; stays on form.
  - Duplicate name → inline **`Already exists`** — fires **live while typing** (async check),
    tested against seeded `Band A — Associate`.
  - Name > 50 chars → inline **`Should not exceed 50 characters`** **while typing**
    (live, not on save). ⚠ Pay-grade limit is **50** (Job Titles is 100 — do not reuse that number).
- **Happy path (verified)**: Save with a unique name → **redirects to the EDIT page
  `/admin/payGrade/{id}`** (it does **NOT** return to the list, unlike Job Titles).

### Edit page `/admin/payGrade/{id}`
- `<h6>` **"Edit Pay Grade"**; the Name field is editable with its own **Save** / **Cancel**.
- A second **Currencies** panel below: `<h6>` **"Currencies"** + an **Add** button.
- On load with no currencies, the grid shows **"No Records Found"** and the app fires an
  **Info-level toast `"No Records Found"`** (`.oxd-toast--info`) — distinct from the green
  success toast; note this when asserting toasts on this page.
- Currencies grid columns: checkbox / **Currency** / **Minimum Salary** / **Maximum Salary** / **Actions**.

### Add Currency inline form (within the edit page)
- Clicking **Add** on the Currencies panel opens an inline **"Add Currency"** block (`<h6>`),
  **not** a modal dialog. Fields:
  - **Currency\*** — OXD dropdown (custom, must click to open), populated with the full ISO
    currency list (~160 options incl. `-- Select --`), e.g. `USD - United States Dollar`,
    `EUR - Euro`, `GBP - Pound Sterling`. Required.
  - **Minimum Salary** — text input, optional (no asterisk).
  - **Maximum Salary** — text input, optional (no asterisk).
  - "* Required" legend, **Cancel** + **Save**.
- **Validation (observed live)**:
  - Min > Max → **both** fields error simultaneously: Minimum Salary shows
    **`Should be lower than Maximum Salary`**, Maximum Salary shows
    **`Should be higher than Minimum Salary`**. Save is blocked.
- **Happy path (verified)**: Currency `USD`, Min `50000`, Max `90000` → row added; grid counter
  becomes **`(1) Record Found`**; the row renders the **full currency name** ("United States
  Dollar", not the code) and salaries formatted with grouping + 2 decimals (`50,000.00` / `90,000.00`).
- **Currency uniqueness by exclusion (verified)**: after USD is added, re-opening **Add Currency**
  shows the dropdown with USD **removed** (159 vs 160 options) — a currency can be assigned to a
  grade **at most once**; there is no "duplicate currency" error path through the UI.

### Delete (list page)
- Trash icon → confirmation dialog: title **"Are you Sure?"**, body **"The selected record will
  be permanently deleted. Are you sure you want to continue?"**, buttons **"No, Cancel"** /
  **"Yes, Delete"** (verified copy, identical to Job Titles).
- `DELETE /api/v2/admin/pay-grades` body `{ "ids": [n] }` → 200.
- Pay grades are **hard-deleted** but deletion is **BLOCKED** when referenced by an Employee's
  salary record: `"This record is in use and cannot be deleted"` (business-rules §11).

### API
- `GET /api/v2/admin/pay-grades` — list.
- `POST /api/v2/admin/pay-grades` body `{ name }` — create (api-reference Admin–Pay Grades).
- `DELETE /api/v2/admin/pay-grades` body `{ ids: [...] }` — bulk hard delete.
- Currencies sub-resource (standard CRUD pattern): `GET/POST
  /api/v2/admin/pay-grades/{id}/currencies` body `{ currencyId, minSalary?, maxSalary? }`.

### Security
- ESS users have **no Admin menu** (business-rules §2); admin endpoints return **403** for ESS
  sessions; unauthenticated requests redirect to login / 401 (business-rules §1).

## Happy Path (TC-001–099)

### TC-001: Admin adds a pay grade with only the required Name
**Category**: Happy Path
**Preconditions**: Logged in as Admin; Name is unique (timestamped test data).
**Steps**:
1. Admin → Job → Pay Grades → click **Add**.
2. Fill **Name** with a unique value.
3. Click **Save**.
**Expected Results**: Save succeeds; app **redirects to the edit page `/admin/payGrade/{id}`**
showing heading "Edit Pay Grade" with the Name pre-filled and an empty **Currencies** grid
("No Records Found"). Returning to the list shows the new row and the counter incremented by 1.
**Business Rule**: Only `name` is mandatory (`POST /admin/pay-grades { name }`).
**Suggested Layer**: E2E

### TC-002: New pay grade appears in the list and increments the counter
**Category**: Happy Path
**Preconditions**: Admin; a grade created this session.
**Steps**: Navigate back to `/admin/viewPayGrades`; locate the new row.
**Expected Results**: Row present in the Name column; counter `(N)` → `(N+1) Records Found`;
Currency column blank (no currencies yet).
**Business Rule**: List reflects created records.
**Suggested Layer**: E2E (asserted within TC-001 run)

### TC-003: Admin adds a currency with min/max salary to a pay grade
**Category**: Happy Path
**Preconditions**: Admin on the edit page of a grade with no currencies.
**Steps**:
1. In the **Currencies** panel, click **Add**.
2. Select **Currency** = `USD - United States Dollar`.
3. Enter **Minimum Salary** `50000` and **Maximum Salary** `90000`.
4. Click **Save**.
**Expected Results**: Currency row added; grid counter `(1) Record Found`; row shows
`United States Dollar`, `50,000.00`, `90,000.00` (full name + grouped 2-decimal salaries).
**Business Rule**: A pay grade may carry one or more currency salary bands.
**Suggested Layer**: E2E

### TC-004: Admin adds a currency with no salary values
**Category**: Happy Path
**Preconditions**: Admin on a grade's edit page.
**Steps**: Add a currency selecting only the **Currency**; leave Min/Max blank; Save.
**Expected Results**: Row saved with empty salary cells — Min/Max are optional.
**Business Rule**: Only Currency is required on the Add Currency form.
**Suggested Layer**: E2E / API

### TC-005: Admin renames an existing pay grade

**Steps**: Open its edit page; change **Name** to a new unique value; Save.
**Expected Results**: Success toast; list shows the updated name; record count unchanged.
**Business Rule**: Name is editable post-create.

### TC-006: Cancel on the Add form abandons creation

**Steps**: Click **Cancel**.

### TC-007: New pay grade is selectable in dependent salary configuration

### TC-105: Minimum Salary greater than Maximum Salary is rejected
**Category**: Business Rule

### TC-106: A currency already assigned cannot be added twice

**Suggested Layer**: E2E

### TC-107: Pay grade in use cannot be deleted
**Category**: Business Rule
**Preconditions**: A pay grade referenced by an employee salary record.
**Steps**: From the list, trash that grade → confirm.
**Expected Results**: Error toast **`This record is in use and cannot be deleted`**; row remains.
**Business Rule**: FK-protected hard delete (business-rules §11).
**Suggested Layer**: API (E2E optional)

### TC-108: Currency is required on the Add Currency form
**Category**: Business Rule
**Preconditions**: Admin on the Add Currency form.
**Steps**: Leave Currency `-- Select --`; enter salary values; Save.
**Expected Results**: Inline `Required` under Currency; row not created.
**Business Rule**: Currency is the only mandatory field on the currency form.
**Suggested Layer**: E2E / Component

## Security (TC-200–299)

**Expected Results**: No Admin menu; direct URLs render a "Credential Required" / forbidden page;
the list and Add form are never shown.

### TC-202: ESS session cannot create a pay grade via API

**Steps**: `POST /api/v2/admin/pay-grades { "name": "Hacked Grade" }` with the ESS session.
**Expected Results**: `403`; no record created.

### TC-203: Unauthenticated access is redirected / rejected
**Category**: Security
**Preconditions**: No session (fresh context).
**Steps**: GET `/admin/viewPayGrades`; `POST /api/v2/admin/pay-grades` without a session.
**Expected Results**: UI redirects to `/auth/login`; API POST → 401/302.
**Business Rule**: Session-gated UI (business-rules §1).
**Suggested Layer**: API + one E2E assertion

### TC-204: Script payload in Name is stored inert (XSS)

**Expected Results**: Payload rendered as escaped text; no dialog; no script execution.

**Suggested Layer**: E2E

### TC-205: SQL-metacharacter Name is treated as plain data
